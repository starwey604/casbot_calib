# SHM 远程调参 GUI：本机绘图，Orin 执行

在笔记本打开调参窗口，通过 SSH 连接 Orin，先看实际关节反馈；点击“开始控制”后调节双臂五字段。渲染、相机交互和视频导出在笔记本运行，SHM 收发、1kHz 执行、控制失联处理和完整记录在 Orin 运行。

这是 2026-11-14 的实施计划，基线 `60ac5e0`；下文新增入口、协议和性能数字分别是计划与目标，尚未实现或测量。本轮仅规划，不启动真实控制。基本 CLI fieldwork 已有现场证据，C03 方向/C04 进一步观察由 GUI 承接；H1 尚无实机采集，不作为 GUI 开发的等待条件。

## 1. 选定架构：SSH 首发，不远程传图像

```text
笔记本                                          Orin
GLFW / ImGui 调参窗口                            SSH bridge（无 PTY）
  ├─ 五字段草稿、状态、曲线 ──控制 SSH─────────→   ├─ RPC / 有界命令收件箱
  ├─ 最新反馈缓存       ←──显示 SSH───────────   └─ 最新反馈订阅
  └─ 本地 MuJoCo 渲染                               │ 本机 IPC
       └─ RGB 双缓冲 → 窗口                      原生 SHM owner
                                                  ├─ 1kHz 状态机 / 五字段
保存 / 导出 ←──独立文件传输（按需）                 ├─ 原生控制租约 / 退出
                                                  ├─ 唯一 /shm_mc 消费者
                                                  └─ 有界异步完整记录 → 磁盘
```

**1kHz 不跨网络闭环。** 鼠标改变目标，Orin 按自己的单调时钟发送最新有效五字段；网络不承担 EtherCAT 周期同步。规划轨迹先完整传输和校验，再在 Orin 求值，不发送每毫秒网络 setpoint。

### 第一版选 SSH，而不是先做 UDP

- 使用现有 OpenSSH 认证和主机密钥校验，不在业务配置保存密码，不新增公网监听端口。
- 控制和显示各用一条独立 TCP/SSH 连接；不复用同一个 ControlMaster 传输，避免显示积压占用同一连接。文件同步不走控制连接。
- `ssh -T` 运行固定 bridge 入口，禁用 X11 转发及 SSH 压缩；stdout 只放协议，stderr 单独日志。参数经受控入口传递并正确转义，不拼接自由 shell 命令。
- SSH 显示流采用有界缓存和最新值语义，不在接收端重播积压反馈。若链路已积压，停止控制租约并重建只读显示连接，而非快速播完历史状态。
- 每包按约 1KiB、反馈 200Hz 预算约 200KiB/s。带宽估算足以支持先做 SSH；实际尾延迟和 CPU 仍需双机测量。

OpenSSH 支持远程命令及安全通道；`-T` 关闭 PTY，压缩在快网络上可能增加开销，见 [ssh 官方手册](https://man.openbsd.org/ssh)。连接复用配置见 [ssh_config 官方手册](https://man.openbsd.org/ssh_config)。

UDP 保留为**显示反馈传输**的后续替换项：如果独立 SSH 显示连接在实际负载下仍无法达到第 7 节的新鲜度目标，且测量定位到 TCP 排队，再实施。那时仍由 SSH 管理会话、开始/停止及记录；UDP 使用同一个反馈结构，包内带会话号/序号，乱序旧包丢弃、丢包不重传，不用 UDP 搬运完整原始记录或首次承担控制。首版不维护双传输自动切换。

## 2. 最大改造点：一个长期 owner，而非多个 CLI 进程轮换

现有 `cpp/src/shm/field_runtime.cpp` 的 observe/run 各自获取 `OwnerLease`、消费状态并创建 Recorder；目前只读观察和主动控制不能同时独立运行。它也没有在线手动收件箱。GUI 不能简单在后台启动旧 observe，再另起 execute。

改为一个 GUI 原生 owner，持续只读收数，内部显式进入/退出控制子会话：

```text
只读 → 正在进入控制 → 控制中 → 正在失能 → 只读
                       └故障→ 正在失能 → 故障会话结束
```

- 提取 codec、时钟、进入/退出、周期调度及记录能力，CLI 和 GUI 共用；不复制一份 CiA402 状态机。既有 CLI 输出和中断处理保持原合同。
- 同一 owner 唯一出队、映射时间、分发反馈。显示订阅者不创建第二个 Channel，也不使用 passive snapshot 代替连续反馈。
- 观测一直保留；正常“停止控制”失能获应答后回到只读，不退出窗口。故障封存旧控制，新控制须显式重读实际起点，无自动 resume/清故障。
- 远程控制连接创建本次 owner，显示连接仅订阅其本机 IPC。控制连接 EOF/bridge 退出使 owner 结束控制并封存退出；显示断开不得留下仍被后台续期的控制。原生 owner 还独立执行租约，覆盖 TCP 尚未识别的静默断网。
- 不安装自动重启控制的 systemd 服务，不借助 tmux/nohup 保活；重连只能新建只读会话。旧 owner 尚未释放时返回占用原因，不抢锁、不重置队列。
- Orin 重启后原会话结束，沿用已有手部背景、prepare/activate 的新窗口流程。GUI 的“连接”不隐式停业务、启动主站或握手。

网络解析、阻塞读写、文件导出在非周期线程/bridge；原生周期只读固定大小已校验快照，发布反馈到有界最新值缓冲，不等待 GUI、SSH、JSON、绘图或写盘。沿用现有异步 Recorder，区分网络丢显示帧和原始记录停录。

## 3. 五字段、回执与断线：先把操作含义做对

### 调参行为沿用原 GUI 决定

- 仅控制双臂 ID12–25；腿/腰/头在主动会话中失能，手部冻结本开机窗口显式背景。只读状态不发送任何控制命令。
- 第一次实际反馈初始化位置草稿；开始控制前原生再次读取实际起点。进入使能阶段保持该起点，进入控制后才接受本次手动修改，不重放历史目标。
- 当前 SHM 无 Kp/Kd 回读：显示配置默认及本次发送值，不标“电机实测增益”；默认 20/2。速度目标、前馈默认 0，不把反馈估算 effort 复制为前馈。
- position / velocity / effort / Kp / Kd 独立，不隐藏加入重力、摩擦、插值或位置平滑。位置目标突变就是显式目标变化；后续若增加平滑，应成为可见、单独实现的操作。
- 鼠标输入合并为至多 50Hz 最新目标；原生按 1kHz 重发最新有效目标。目标停止变化仍须有有效 GUI 租约。
- GUI 先校验输入；原生重复校验有限值、范围和整数可表示性。越界目标拒收并保留最后有效值，界面显示原因，不夹取。参数范围取 SHM profile/codec，不把旧 SDK 可调范围当设备能力。
- 手动调参保持当前现场探索的 URDF 输入限位；速度目标范围不等于设备真实速度限制。位置反馈越界只告警，速度观察默认告警、可选结束，沿用既有调参台决定。H1 和回零继续各自的规划/碰撞及观察合同，不能因为 GUI 手动入口而放宽。

### 回执不是“执行完成”

每次控制有新 `control_id`，每次五字段更新有递增 `revision`。回执区分：

1. **已接收/拒绝**：原生校验结果；
2. **已入队**：首次成功写 SHM 的 revision、Orin 单调时刻及编码后五字段；
3. **实际反馈**：位置/速度/估算 effort 与状态字，独立展示。

成功入队不标为驱动已采用或物理已到位。开始/停止使用 request_id 幂等处理；控制结束后旧 revision、迟到开始、旧心跳均不能重新开启控制。STOP 在原生收件箱中优先，普通目标更新仅留最新一个。

### 原生控制租约覆盖静默失联

本轮 C05 已观察停写三秒仍保持使能；SSH/PTTY 主动关闭虽触发失能，但新 GUI 无 PTY，不能依赖相同信号链。

- 建议首版 GUI 主循环每 100ms 参与一次租约续期，租约期限 1s；数值是新 GUI 的开发默认，可在设置中显式调整并留档，不回写旧 CLI/profile。
- 续期使用原生发出的、有 Orin 单调到期时刻的一次性 challenge，至多一个有效 challenge；GUI 主循环处理后回应。原生按原始到期时刻判断，迟到/重复响应不延长租约，避免 TCP 中积压的心跳被释放后重新续命。
- 网络线程不能替卡死的 GUI 自动回答续期；UI 正常缩小/隐藏窗口仍运行监督 tick，可以续期，停止绘图不停止监督。
- 显示连接失败或没有新的有效反馈时，GUI 不继续续期，并优先请求 STOP。续期响应带主循环最新处理的遥测序号；原生用该包自身的 Orin 发送时刻核对年龄，超过租约期限不续期。显示包还带主站帧号，原生反馈超时独立生效，不能靠重发同一反馈续命。
- EOF、租约超时、明确 STOP 或驱动/通信故障，原生进入既有失能退出，记录原因和应答；不是停写后等待电机 watchdog。
- 未获得失能应答显示“失能未确认”，失联时显示“连接丢失，失能状态未知”；只有回执到达才显示“已收到失能应答”。驱动失能也不标成物理已停稳。
- 原生进程被 SIGKILL、内核卡死或总线故障时无法承诺软件失能；保留现场独立物理保护。该边界不通过无限重试/重启主站掩盖。

## 4. 协议与时间：显示抽样，原始证据不抽样

网络协议不直接 memcpy C++ struct：显式版本、长度、字节序和类型，整数纳秒/帧号按整数传输，长度有上限。低频 RPC 用有界长度帧 JSON；高频遥测用固定字段二进制，浮点字段明确 float64，不引入 MessagePack/protobuf 新依赖。目标更新是约百次/秒以内的小消息，不进入 1kHz JSON 解析路径。

首版消息覆盖 hello、只读状态、开始/停止、新目标、租约、设置及应用回执、记录状态。hello 返回协议版本、model_context、14轴顺序、boot_id、workspace_id、非目标轴/手部策略；本机模型必须与实际上下文匹配，不能悄悄回退默认模型。boot_id 绑定本开机窗口，不冒充设备身份。

显示反馈包含：

- owner/控制会话及显示包序号、主站 frame_counter；
- 原始 source_timestamp_ms、Orin observation_time_ns、clock_segment、receive_mono_ns、遥测发出时刻；
- 双臂 q/dq/估算 effort，全部 35 槽状态/模式/错误，双手原始状态；
- 当前阶段、最后入队 revision/编码后五字段、退出应答及记录状态。

遥测每 5ms 发布最新一帧，未展示的中间帧仍在 Orin 全量保存；画面仅由实际反馈驱动。非双臂关节未完成可靠运动学换算的部位显示原始值/状态，不套双臂 codec 来驱动模型。图中这些部位采用固定模型姿态并明确标签。

时间沿用既定 A 语义：主站毫秒 stamp 在 **Orin 同机**配对墙钟/单调钟，表示主站转换时间附近，不改为笔记本时间。网络另存本机接收时间，画面时间轴用原始 observation 时间及分段；跨机不能直接相减两个 monotonic 时刻声称单向延迟。

性能诊断可用请求往返测 RTT，以本机收包后到绘图提交测本地显示耗时；如展示跨机包年龄，只给带往返不确定度的估计。A/H1 分析始终读取 Orin 原始记录，不读 200Hz 显示流。首版不对遥测做预测、补帧或外推。

沿用现有主题、中文字体、输入控件、轴高亮和轻量 CAD 资产，不另造配色体系。布局优先让当前轴、实际姿态和停止动作同时可见；左侧显示真实 ID 和中文名称，减少这次 ID1/ID12 的混淆。只读/控制/失能状态用明确文字，颜色作辅助。不加实物辨认勾选、review 表单或上传前提。

### 可以直接复用与需要解耦的部分

- `fieldwork_scene.py`：MuJoCo 静态颜色/深度缓存，动态双臂合成；只前向更新姿态、不推进仿真。
- `fieldwork_display.py`：同源轻量显示网格与变化检测。
- `fieldwork_frames.py`：本机渲染器到窗口的 memfd RGB 双缓冲；图像不跨 SSH。
- `fieldwork_window.py`、`fieldwork_gl.py`、`fieldwork_damage.py`：GLFW/ImGui/OpenGL 和增量绘图。抽出会话无关窗口壳，保留软渲染降级。
- `fieldwork_gui.py` 中的 Desk、`fieldwork_control/launch/worker/observer` 仍绑定 hardware_field、SDK scope、旧工作区和 CDR：不直接改几个字符串冒充 SHM 后端。用新 SHM 会话适配层替代这些职责，提取真正中性的控件/渲染初始化。
- 限制编辑器的 UI 可复用，SDK 模式 RPC/DDS 超时、ROS 发送频率菜单、SDK watchdog 删除；替换为 SHM 1kHz 固定周期、原生租约、反馈/发送失败超时和 SHM Mock 实际配置。

首版复用 RGB 双缓冲，不同时重写为全 GPU 零拷贝渲染。性能测出 readPixels/上传确实占主导时，再比较直接渲染到纹理的收益。

## 6. 工作区与部署

### 完整记录在 Orin，笔记本只缓存显示和操作元数据

- 一次 GUI 工作区只录一份全量反馈/原始 bin/时钟配对，控制子会话用单调区间和索引引用；不再为控制额外起原始 recorder。
- 每次控制保存实际入队命令、设置版本/回执、事件及退出结果。Orin 会话位置在窗口可见。
- 本地显示曲线用有界环形缓存，不把全部 CSV 载入内存。完整记录额度在 Orin 端执行，默认沿用每工作区 512MiB 软额度，包含原始 bin、CSV 和控制记录；额度满/磁盘写入失败保留已写前缀，告警停录，不堵住控制。窗口显示远端记录大小和余量，不把本地缓存大小当完整记录大小。
- “保存会话”先在 Orin 封存可恢复前缀/快照，再独立同步到本地；不在控制连接传大文件。保存失败显示远端路径与重试入口，不删除远端原件。
- 复用已有容量保护、快照和前缀保存的设计，新增 SHM 清单版本/读取器，不伪装成旧 CDR 记录。早期完整 CSV/bin 开销先测量，不把压缩系统重写列为手动可用的前置条件。
- 历史恢复只读，不自动连接或发送。视频在本机从同步后的实际反馈流式生成，完整记录缺失时明确范围；沿用既有编码取消/失败处理，不以网络抽样替代完整视频源。
- 保存零位仍采实际位置，以 Orin 仓库 `fieldwork/zero.yaml` 为权威文件，沿用原子替换/Git 忽略约定；本机可留导出副本，不自动拿另一台机器的旧零位覆盖远端。回到保存零位由既有 C3/Coal 规划能力生成单程参考，传到 owner 执行，与手动串行，不暗加补偿。停止时显式失能，不以“暂停发包”实现暂停。

### 两端依赖分开

- 本机：现有数学/模型环境和 `fieldwork-gui` 图形依赖，复用锁定依赖，不顺带升级 MuJoCo/ImGui；单独 setup/启动脚本选择正确 Python 与 GPU，软件渲染显式可选。
- Orin：现有 CMake CORE+SHM，新增原生 owner 目标和轻量标准库 bridge；GUI 手动操作不要求 Orin 安装 MuJoCo、ImGui 或 X server。H1 数值规划仍使用现有 `.venv-shm`。
- SSH 使用用户现有 key/agent 或正常交互认证，保留 known_hosts 验证，不自动安装密钥、不硬编码口令。启动器建立新会话需要的连接，复用远端工作区令牌完成只读订阅。
- 私有 `--mock` 走同一 owner/协议：既能全本机运行，也能连 Orin 上独占私有 SHM Mock；不落到真实 `/shm_mc`，不接管其它实例。

计划入口：`fieldwork/shm/run.sh gui --host nvidia@172.16.0.10 --remote-repo /home/nvidia/casbot_calib_shm`；本地私有演练 `... gui --mock`。这是新入口，尚不可执行。GUI 使用单独图形 Python 选择规则，不复用当前 run.sh 给 h1/a-evidence 的 venv 判断。现有 CLI 不受影响。

## 7. 性能预算与检查方式

以下是首版目标，真实环境测量后报告结果及瓶颈，不把预算写成已达到：

| 路径 | 初始预算 |
| --- | --- |
| Orin SHM 收发/目标求值 | 1kHz，晚到取当前参考，不补发历史帧 |
| GUI 目标发布 | 合并到最多 50Hz，原生下一可用周期采用已接收新目标 |
| 遥测 | 200Hz 最新帧；约 200KiB/s 量级，记录保持完整 |
| UI 监督/输入 | 60Hz，与重绘解耦 |
| 本机 3D / 活动窗口 | 硬件渲染目标 30fps；静止窗口 2–5fps，隐藏停绘 |
| 直连网络 | 小消息 RTT p99 <20ms；本地收包到绘图提交 p99 <50ms |
| Orin 原生调度 | 相对同配方无 GUI 基线，发送间隔 p99 增量 <0.2ms；最大间隔/超期计数单列 |
