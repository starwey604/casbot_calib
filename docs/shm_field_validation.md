# SHM 现场逐组确认手册

先把**整帧里的各部位怎么处置，以及接管、首帧和停止会发生什么**测清楚，再把策略写进 `shm_executor` 和 SHM Mock。现场由代理运行选定用例、解释记录，用户观察机器人并反馈；一次只运行一个用例，不自动跑完整机。

**当前状态（2026-11-14）：已有独立逐轴原型，ID12控制流程与可见运动已确认；已提供`fieldwork/shm/run.sh`及共享原生`shm_executor`，支持C00–C06的双臂现场流程、持续观测、离线报告和观察登记；头部主动运动、腿腰保持配方、手部动作仍待补。** C00–C03已有部分证据，见末尾台账，不能将它们整体标为未测或已完成。完整操作顺序见[SHM CLI手册](../fieldwork/shm/README.md)。旧ROS入口移至`fieldwork/ros/`，原根目录脚本仍转发，不能把SDK的域号参数带到SHM。已有软件证据见 [Jetson 接口勘察](jetson_shm_interface_recon_20261113.md)，原 ROS SDK 工具继续使用 [fieldwork 手册](../fieldwork/ros/README.md)。

执行器、物理 Mock、Humble/Orin 构建与上层接入的实施顺序见 [SHM 代码移植计划](shm_migration_plan.md)。

用户随后批准先用[双臂原生试验程序](shm_joint_test.md)探索：机器人固定支撑、腿腰头可失能，先测双臂14轴，全部状态打印；相对当次起点±0.5rad须先检查双向URDF位置/参考速度限位，逐例运行、观察反馈。用户随后明确关闭此逐轴原型碰撞检测，其它标定入口规则不变。此原型不替代本手册全部用例。原型与新`shm_executor`现共用`cpp/src/shm/field_runtime.cpp`，没有两套模式/退出状态机。

## 1. 已经确定的前提，直接沿用

### 停业务后，在本次开机窗口内独占测试

由用户安排好承重、支撑和物理停止手段后，在 Jetson 上执行：

```bash
sudo systemctl stop zero_calibration.service arm_debug_tool.service
sudo bash /workspace/embed_fusion/bin/launcher.bash stop

# 停业务完成后，只启动 EtherCAT 主站；测试另开终端。
sudo bash /workspace/embed_fusion/bin/run_ethercat_station.bash
```

厂家停止脚本也会停止旧主站，且包含 SIGKILL；执行前不能依赖原业务继续承重。若出现模块选择提示，需完成全部业务停止。具体覆盖范围见[停业务流程](jetson_shm_interface_recon_20261113.md#用户确定的停业务后独占测试流程)。

停业务完成时核对一次原控制程序退出。此后直到下次 Orin 重启，**按用户指定假设认定没有其它程序启动插队**；不增加持续抢权、自动恢复业务或永久禁用服务的机制。重启后重新走上述流程，不续接旧控制会话。

### 软件接口与时间约定

- 本次使用 35 槽兼容 ABI：命令 744 字节、状态 696 字节；不是主站内部的 40 槽结构。方向、实际零偏和定点转换沿用勘察结果，不因去掉 ROS 而去掉。
- 一个原生进程拥有 SHM 收发，再分发给记录器、控制和界面。厂家客户端构造会改队列索引，接收会出队，不能另起一个厂家客户端旁录。
- 命令 `effort` 是前馈，反馈 `effort` 是估算总输出；不能把后者复制成前馈。现场手动确认默认不隐藏叠加重力或摩擦补偿；若某用例需要补偿，配方中明确写出。
- 反馈没有 Kp/Kd 回读；保存发送值，不能标成“模组生效增益”。

A 路径的时间定义已确定，后续脚本照此记录，不再把出队时间当观测时间：

```text
source_timestamp_ms = 状态帧原始 timestamp
clock_offset_ns     = Jetson 同机配对墙钟 W0 - 单调钟 M0
observation_time_ns = source_timestamp_ms * 1,000,000 - clock_offset_ns
elapsed_s           = (observation_time_ns - first_command_mono_ns) / 1e9
```

`W0` 用两次单调钟读取夹住墙钟读取，保留配对区间与不确定度；均在 Jetson 上取，不用 SSH 往返估计偏移。另存 `receive_mono_ns` 和实际发送单调时刻用于排队、调度诊断。`first_command_mono_ns` 对应 A 分析所用 `commands.csv` 执行流的首条成功写入命令，不是进程启动时刻。SHM 的初始化/失能/切模式也要写命令帧：这些另标阶段，保存 `first_shm_write_mono_ns`，不能混同于首条轨迹/测试执行命令而挪动 A 的选窗原点。

现有状态 stamp 是主站转换结束附近的 `gettimeofday()` **毫秒墙钟**，映射不会把它变成驱动采样时刻。同一状态行的 q/v/effort 共用此时间；帧号不乘 1ms 造时间，缺帧不补样，同毫秒多帧保留原始记录、拟合时再按时间组处理权重。持续保存时钟配对用于检查跳变；墙钟跳变处分段，不能排序或平滑掩盖。A 的共同投影/Fourier 数值内核先复用，改为显式消费观测时间；时钟映射及配对记录已进入新执行器：每秒配对一次，偏移变化超过5ms加配对区间时开新段，配对间跳变的精确边界保留原始字段供离线定位。A消费者的显式观测时间接入仍待实现。

### 第 4、5、6 项采用开发默认，源码到位后复核

用户2026-11-13决定：**命令采用细节、通道更新/滤波细节和亚刻度力矩可辨识性，列为后续确认项，不作为 SHM 执行器、Mock、A 路径适配及现场探索的开工条件。** 当前按下面的明确默认推进；这些是开发约定，后续源码若不同，修改相应适配与 Mock，不改写旧记录。

| 项目 | 当前采用的默认 | 留到源码/后续数据确认 |
| --- | --- | --- |
| 4. 命令采用 | 私有 Mock 按已观察的容量 2 建有界 FIFO，主站模型每周期取一条，无新命令则沿用旧命令。发送器每 1ms 按当前单调时间计算目标，不积攒待补发的历史参考。周期目标帧入队满时跳过本次并记录，下一周期计算新目标；不无限等待、不由生产者清空队列。持续无法发送按通信失败结束，不因单次队列满就结束控制。状态切换帧未写成功时不得推进相应状态机。命令帧号递增用于记录，Mock 默认不因旧/重复帧号拒收；成功入队只表示入队成功 | 真实队列严格 FIFO 还是取最新、满队列行为、主站是否校验帧号；持续发送失败的处理复用执行器通信超时，不等待这些细节确认后才开发 |
| 5. 反馈通道 | A 暂按同一状态帧的 q/v/effort 对齐到该帧观测时间，直接消费已有数值；不额外猜测滤波或补偿通道延迟。Mock 基线同一物理步生成三通道，再编码；没有已知滤波就不凭空增加滤波。保留所有原始帧，不按数值相同判旧帧，也不从 count 推造逐轴有效性 | 各通道真实刷新、滤波/估算、通道间延迟、缺更新时的保留规则及有效性；确认后再决定是否需要改 A 的观测模型 |
| 6. 力矩信息 | 先用现有 int16 接口和软件尺度 0.01 Nm/LSB；Mock 在反馈编码时体现整数刻度，命令按已找到的截断规则编码。现有探针先通过这条真实整数边界运行、保留结果，不等待高精度入口。不人为加入噪声让亚刻度估计看起来可用 | 源码是否有更高精度力矩/电流、实际噪声与滤波，以及原亚 mNm 探针在此接口下还剩多少辨识信息 |

这三项影响后续时延/误差解释和探针效果，不阻断迁移。1kHz 稳态下 FIFO 与取最新可能差异较小，积压时仍可能不同，因此保留实际发送和反馈记录即可，不先增加专项实机验证。亚刻度周期估计是否有效由数据决定：算不出或信息不足就记录原因，不把小于一个刻度直接判成可用或不可用，也不为得到结果去掉量化。

## 2. 按哪些部位确认

| 部位 | SHM 位置 | 本轮要确认的关系 |
| --- | --- | --- |
| 左腿、右腿 | `joint_commands/status[0..5]`、`[6..11]` | 支撑条件下的使能、保持、释放及对上身测试的影响；腿部有串并联/四连杆转换，先不做通用单轴位置 jog |
| 腰 | `[28]`，yaw | 机械固定与驱动设置的关系；保持还是释放，有无持续异常出力 |
| 头 | `[26]` pitch、`[27]` yaw | 两个槽与实物、方向对应；双臂运动时维持什么指令 |
| 左臂 | `[12..18]` | 肩 pitch/roll/yaw、肘 pitch、腕 yaw/pitch/roll 的对应、方向和第一帧衔接 |
| 右臂 | `[19..25]` | 同上；左臂测试时右臂如何保持，反向也测 |
| 左手、右手 | 独立 `hand_commands/status[0]`、`[1]`，每手 6 个原始项 | 手模式、槽与实际动作，以及双臂测试时的保持策略；不套用电机关节的模式/单位 |
| 保留槽 | 电机关节 `[29..34]` | 保留字节记录和明确填充规则，不作为手指，不做主动运动试探 |

手的 6 项不能直接等同于 ROS 的 20 个手指关节；手部模式与尺度未清楚前只读。腿部也不直接套用双臂的 SI 转换。先完成全轴只读和支撑下的背景处置，再做头/单臂定位、另一臂、手部；腿部运动学控制另立用例，不混入双臂迁移首轮。

## 3. 先定义完整背景帧 F0，再改变一个部位

**SHM 是完整结构体，不是“省略其它轴名就让旧运控保持”。** 目前没有已验证的逐轴有效掩码；`joint_count=14` 也不能当作选择双臂 14 轴的掩码。本次原运控命令观察到 count=29、hand_count=2，状态 count=0 仍含轴值，不能靠 count 判断逐轴反馈有效性。

每个主动用例先生成并展示一份背景配方 F0，逐组列出：

- 原始槽、目标位置来源、速度/前馈、Kp/Kd、模式、控制字，以及手部完整命令；明确哪些字节会变、哪些不变。
- 测试轴从本次新鲜实际位置初始化目标，速度和前馈默认 0；固定保持目标不跟随每帧反馈漂移。不重放上次测试的旧目标，不套用 Mock 休息姿态，也不自动回编码器零位。
- 非目标组分别选择本次明确采用的处置：**支撑后失能**，或**指定位置/增益的使能保持**。尚未测试的策略标为“本用例试验设置”，而非已验证能力。初次主动试验可依靠现场支撑和独立物理停止开展，不要求先用运动证明运动安全。
- 手部、保留槽、count 等也有明确编码规则；不能将整帧清零后只填双臂，更不能默认使能全部轴。停业务前的命令快照用于理解原设置，不自动重放到新主站。

若某背景组的处置无法在现有支撑条件下安全试验，就暂停依赖它的主动用例；只读、私有 Mock 和其它独立开发仍继续。不故意把非目标轴目标设成 0 来试“会不会回零”。

### 执行时的具体边界

- C01/C02 首先在支撑条件下测，先确定本轮的受控结束配方，再扩大 C03。模式切换遵循 PDF 的先失能再切模式要求，不能带使能切换；`0x06 → (Statusword & 0x006f)==0x21`、随后 MIT `mode=-1`、`0x0F → (Statusword & 0x006f)==0x27` 的具体写入阶段、应答和超时均记录。状态字应答与物理保持/释放分开记录，不直接把 `0x06` 定为正常退出或急停。
- C03 初始建议每向 **0.2°、每段至少 2s 的平滑参考**，实际幅度/速度/增益在现场用例中明确，不能因为没看清就自动放大。正反动作与返回段是本用例波形，不恢复 H1–H4 已删除的结束回位误差门禁。通常参考检查实际模型、起点、限位及碰撞；本轮用户另行授权的`shm_joint_test`关闭碰撞、采用±0.5rad/每段5秒，见[原生试验](shm_joint_test.md)，不改其它标定入口。无工具/台架的模型不能证明带工具环境。
- 腰机械固定时，“位置没动”分不出释放还是持续顶住夹具，必须结合控制字、状态字、输出变化及可用驱动诊断；证据不足就记“无法区分”。不靠人手推正在使能的机器人来测刚度。
- C05/C06 不预设 watchdog 超时，也不通过等待断流证明机体会自保护。停止写入可能让旧目标无限延续；试验前约定有限观察时长和现场终止动作。结束后新会话重读起点，不恢复旧轨迹。
- C06 的存活探针只做 `O_RDONLY/pread` 快照，不构造第二个厂家客户端；快照用于故障取证，不能充当一致控制反馈。意外故障导致记录缺失时保留缺口，不补造。
- C08 的零 PD、前馈输出仅在所选轴有支撑、幅值已安排时测试；默认值不代表承重能力。当前力矩编码为 **0.01 Nm/LSB**，先列出编码前后的实际值；被截断为 0 的微小前馈不能算有效激励。独立已知载荷/力臂验证另做子用例，不能拿拟合中的 nominal 重力自证物理尺度。
- 实际驱动错误、通信/模式故障结束当前控制会话，只记录，不清故障、不自动重新使能或续采。故障注入先在私有 Mock 做，不向实机写假状态/错误码，也不为试验主动制造主站崩溃。

## 5. 后续脚本应怎样工作

现有独立入口为`bash fieldwork/shm/run.sh`，不让旧ROS命令悄悄切换传输。脚本自动定位仓库，原生周期进程不经ROS/distrobox；仅系统Python标准库用于编排/报告。

```bash
bash fieldwork/shm/run.sh list
bash fieldwork/shm/run.sh observe --duration 10
# 默认只预览；追加--execute才接管/使能/发本例命令。
bash fieldwork/shm/run.sh run C03 --joint-id 13 --hand-background 明确的command.bin
bash fieldwork/shm/run.sh run C03 --joint-id 13 --hand-background 明确的command.bin --execute
```

C00用`inspect`，C01–C06用`run Cxx`；`prepare`及`activate`各自需要`--execute`，不会隐藏在用例启动中。C02的`--variant hold/disable`分别标记保持/退出观察重点，均在有限保持后失能退出；C04可单独对比`--other-arm hold/disabled`，其它背景仍是用户已授权的失能/冻结手部设置。C05静默时仅接收，结束后请求失能；C06显式选`--termination sigterm/sigkill`，后者不补发失能，现场使用继电器。C03当前只支持双臂12–25，C07/C08没有主动下发入口，不能把整个手册称为已全部实现。

1. **先列出/预览，再显式运行一个用例。** 预览包含部位、F0策略、命令差异、增益编码及退出配方；提供`--snapshot`可离线列起点/限位/原始位置，否则明确执行时重读。支持只读模式；私有协议夹具用于软件联跑，物理Mock尚未完成，开发测试不连接真实`shm_mc`。
2. **代理负责运行与记录，用户负责现场观察。** 单个用例运行完停在检查点，用户反馈“哪个关节动了/没动、方向、是否松了/抖了”等自然语言；代理保存原话、解释数据，再按用户指示继续/重做/停止。不自动循环全轴，不把“没有反馈”当通过。
3. **等待反馈不占住控制周期。** 原生 owner 负责定周期收发，SSH/Python、磁盘写入和用户思考不能阻塞它。等待期间是否继续固定目标保持、何时退出，由本用例明确的配方决定；没有已选配方就不能留下无人管理的主动控制。显示正在保持还是已退出，不把提示符当停机。
4. **停止和失联走明确的执行路径。** 正常结束、用户中止、监督端 EOF/SSH 断开分别记录并执行已选的退出配方；若周期进程已死，不能声称还能软件下发停止，交由现场物理停止。不可用“关进程/关闭窗口”代替已验证的物理停止。
5. **首轮循环目标为 1ms，报告实际节奏。** 记录成功入队时刻、失败/等待和读取缺口，不先假定硬实时或所有轴都新采样。不继承 ROS 主机的位置插值假设；插值若由新执行器承担，明确参考时刻及算法。
6. **结果一例一存，新尝试另建记录。** 正常检查点可以开始下一例；故障会话不能 resume。读旧记录或恢复缓存不自动连接硬件，后台不自动启动旧业务。

## 6. 每次记录什么，怎样落结论

当前脚本每例使用新目录，自动路径位于`artifacts/shm_fieldwork/`，也可显式`--output`。当前产物如下：

| 产物 | 用途 |
| --- | --- |
| `case.json`、`native/background.bin` | 用例/部位、模型路径、背景策略、参数/退出配方；原生运行后保存按新鲜起点构造的完整F0。实物安装/负载观察可用note追加，不要求上传前提表 |
| `native/commands.bin`、`feedback.bin`、`queues.csv` | 全部35槽及双手原始命令/状态、各字段读取的队列诊断；C06独立`probe/`存被动记录和`passive_commands.bin`，不计为成功发送 |
| `native/commands.csv`、`feedback.csv` | 双臂SI命令/反馈、35槽状态/模式/错误码、帧号、原始stamp及观测/接收时间。原始整数/完整控制字在权威bin中保留，不靠14轴规范化替代全帧 |
| `native/clock_pairs.csv`、`events.csv` | 时钟配对与跳变、初始化/首帧/状态变化/停止写入/进程退出、队列和周期异常 |
| `observations.jsonl/md` | 用`note`离线追加用户原话、阶段、记录时间及结论；记录时间不冒充观察发生时刻；视频可另附路径 |
| `process.json`、`terminal.log`、`result.json`、`report.md` | 实际命令/自有PID/退出码，软件结果、双臂及全槽/双手变化、时钟/阶段、用户观察；原生另存`result.txt`，未封存时恢复完整前缀、不resume |

记录保存全身，不只存规范化后的双臂。尤其要能还原**旧业务退出 → 仅主站 → 新 owner 初始化/首条 SHM 命令 → 模式/使能 → 首条执行命令 → 正常结束或断流**的边界。命令入队成功、反馈状态变化、用户观察到动作是三个事件，分别标注；不将它们直接相减称为驱动单向延迟。

结论用四种状态即可：`not_run`（未测）、`observed`（有明确观测）、`inconclusive`（试过但不能区分）、`contradicted`（与采用的假设相反）。`observed` 必须写具体行为和适用设置，不能只写“通过”。`execution_completed` 仅表示脚本执行结束；物理停止、尺度和保持能力各有自己的结论。用户指定的无插队安排单列为运行假设，不冒充观测。

首轮台账如下；“部分observed”只覆盖已记录设置，其余子用例仍为not_run：

| 要确认的事 | 用例 | 结论会改变什么 | 当前状态 |
| --- | --- | --- | --- |
| 腿/腰的支撑、固定与驱动设置 | C00–C02、C04 | 双臂测试可用的完整背景配方 | 部分`observed`：用户确认固定支撑、允许腿腰头失能；ID12例记录失能命令及状态。未比较其它保持配方/物理释放行为 |
| 头、对侧臂、双手的非目标保持 | C01–C04、C07 | 非目标组每帧具体填什么 | `not_run` |
| 首帧与使能衔接 | C01 | 执行器进入状态机、初始化目标 | 部分`observed`：完成新主站握手、ID12全双臂模式/使能应答；用户观察运动正常，详细首帧物理行为待单列 |
| 正常结束与用户停止 | C02 | 执行器退出状态机和等待反馈策略 | 部分`observed`：ID12正常结束收到失能应答；持续保持、主动中止和物理停止行为未分别验证 |
| 断流、发送器死亡 | C05–C06 | 失联处理、现场停止安排及 Mock 故障行为 | `not_run` |
| 槽号、方向、零位与手模式 | C03、C07 | SHM profile 的映射与模型坐标绑定 | 部分`observed`：ID12可见运动正常，完整方向/零位/其余轴/手部未确认。用户另尝试ID13并报告Orin疑似卡住，原因和该例执行结果待查 |
| 五字段响应与物理力矩尺度（后续） | C08 | 复核控制响应与可用标定激励；当前先沿用已知换算，不阻断主线 | `not_run` |

现场结果先落进逐例记录，再更新新 SHM profile、执行器和 Mock 的对应行为；与假设相反就改实现，不把现象改写成通过。Mock 需保留真实队列消费、旧命令延续和 0.01 Nm 量化，而不是沿用 SDK 断流保护来掩盖差异。旧封存数据不回写。

下一步按[ID12之后的fieldwork优先计划](shm_migration_plan.md#6-id12之后先交付明天可用的shm-fieldwork)，单用例入口、记录/报告及持续观测已实现并用私有协议夹具验证，下一步在Orin编译安装并开展现场用例，再补完整物理Mock；现场由代理运行、用户观察，逐项填台账。正式动力学观测另核对逐轴刷新/采样、滤波与尺度；本手册不把 1kHz 软件交换变成旧 S3/S4 的 4kHz 采样证据，也不恢复现场 H1–H4 已删除的质量/review 门禁。
