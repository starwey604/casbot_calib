# 手动调参限制与状态反馈改造计划

状态：按四轮逐轮交付。第1轮已实现可见状态、启动等待/取消和独立只读观测，核心路径回归通过；第2–4轮待实施。下文描述完整目标，不表示所有行为已切换。

目标是让操作者看清“正在等什么、哪里超限、当前仍在发送什么、下一步能做什么”。限制触发后按含义等待、拒绝本次输入、告警、暂停参考推进或结束当前控制，不再统一变成一条含糊的故障信息。

范围为手动GUI及其SDK Mock执行链。既有H1–H4、S2、S3/S4入口保留自己的规则；SDK执行、通信、模式故障仍结束当前控制会话，不清故障、不自动重申请控制或续发旧命令。GUI窗口和只读观测不因控制会话结束而一起退出。

## 当前第1轮的行为与剩余工作

- 已接入：后端结构化事件、中文逐轴值/阈值、等待时长、启动条件等待/取消；条件恢复仅继续仍有效的待启动请求。
- GUI工作区与控制会话分离：连接先只读，每次开始建立新控制；控制结束后观测保留，通过“重读 / 新控制”显式建立新起点。故障旧会话不resume。
- 心跳、取消和状态走管道，记录归档失败不会阻断这些通道；只读记录器写盘失败继续收数并告警。控制专用原始记录器仍是控制依赖，退出时明确结束控制。
- **当前运行`observed_limit`仍结束控制，不是暂停。** 可调设置/软阈值动作在第2轮实现；平滑位置交接、连续名义重力辅助和真正暂停在第3轮实现。默认0前馈仍可能撤掉待机支撑，不能将这轮状态改造当成未操作轴运动已修好。
- 启动静止阈值仍为0.02 rad/s、连续时间0ms；默认24小时控制截止和完整H1 profile依赖留待第2轮去除。第4轮再接Mock总请求上限与设备设置。

当前使用方式见[现场指南](../fieldwork/README.md)。本机验收汇总在`artifacts/fieldwork_limits_round1_delivery_v1/delivery.json`，其中区分协议夹具、原生机械Mock和实际GUI证据。

## 操作者首先应该看到具体状态

启动前速度条件未满足时，界面持续显示：

> 等待停稳：左肩滚转 0.0278 rad/s，高于启动阈值 0.0200 rad/s。尚未切模式、未发送指令。条件满足后继续本次启动。［取消启动］

当前代码已在`WAIT_FEEDBACK`中等待，并非只要超过0.02就立即退出；问题是没有可见的逐轴原因，且等待分支还混着10秒启动超时。改造后：

- “开始发送”保留为待执行请求；只读反馈持续更新。
- 列出全部未满足条件及对应轴，不只报告最大轴。
- 条件满足后自动继续这次已请求的启动。启动速度阈值和连续满足时间都可配置；连续时间默认0ms，保持现有启动条件语义，不另加隐藏等待。
- 等待不再因“人还没调好参数”超时结束；已等待多久始终可见。
- 操作者取消、断开或关闭窗口后，待启动请求失效；不能稍后自行启动。

运行中位置/速度超限则显示不同信息，例如：

> 右肩滚转反馈速度 0.786 rad/s，超过运行阈值 0.750 rad/s。已暂停位置参考推进，保持输出仍在发送。［继续］［结束控制］

“暂停参考”只表示不继续推进位置目标，不宣称机器人已经停止。没有厂商stop RPC时，不显示“已急停”。

## 按触发含义处理，而不是统一退出

| 类别 | 典型条件 | 默认处理 | 何时继续 |
| --- | --- | --- | --- |
| 启动前置条件 | 还没反馈、轴未停稳、等待允许的起始模式或服务发现 | 显示原因并等待，不切模式、不发命令 | 条件满足后自动继续仍有效的启动请求 |
| 操作者输入不合法 | 输入越出操作范围、无效数字、短轨迹端点超界 | 输入框旁说明；拒绝这次修改，保留已接受目标，不关闭窗口 | 输入修正后可直接应用；不另加确认勾选 |
| 软件运行观察阈值 | 实际位置/速度越过操作阈值、未操作轴漂移 | 根据控制方式告警或暂停参考，显示实测值/阈值/动作 | 告警恢复自动消除；暂停后由用户点继续，不自动重放轨迹 |
| SDK执行/通信/模式故障 | 发送器退出、反馈失联、模式切入失败、运行模式丢失 | 结束当前控制；保留原始原因、只读监视和可用记录 | 故障不自动resume；现场处置后显式新建控制会话并重新开始 |
| 设备/仿真饱和 | Mock配置的前馈或总输出上限 | 明示设备配置上限和可观测的截断/反馈情况；不把饱和统一写成程序故障 | 用户调参数；不通过自动放宽阈值“恢复” |
| 纯录制问题 | 磁盘写入失败，但反馈和发送器仍正常 | 红条提示“当前未录制”，暂停自动短轨迹；保留手动控制选择 | 用户修复录制或明确结束/继续手动；记录失败不能写成采集成功 |

如果记录器退出同时意味着唯一反馈来源丢失，则属于通信故障，结束控制；不能假设“只是文件没写进去”。格式损坏、缺轴、NaN等来自执行链的数据问题也结束控制，不将坏帧当可重试的普通输入。

### 运行中的软阈值要和控制方式对应

- **位置调试**：位置/速度观察阈值默认触发“暂停位置参考推进”，维持该模式已经明确启用的PD与重力辅助，不突然撤掉支撑。操作者也可将动作改为“仅告警”或“结束当前控制”。
- **原始五字段**：保持五字段的直接含义，观察阈值默认仅告警，可选择结束当前控制。“冻结position”并不能停止零PD/非零effort下的运动，不提供名不副实的暂停按钮。
- 初始条件等待可以自动继续；运行暂停、SDK故障和失联后的恢复不是同一种情况。

## 在GUI里分开调整操作范围和观察阈值

新增“控制设置”区域，不再用一个`maximum_velocity_rad_s`同时承担多种职责。

| 设置 | GUI表现 | 应用与触发行为 |
| --- | --- | --- |
| 各轴位置操作min/max | 每轴可编辑；同时显示URDF名义范围及来源 | 拒绝越界输入并说明，不修改URDF或自动移动关节 |
| 目标速度输入范围 | 可编辑，标明是MIT速度目标范围 | 不当成实际运动限速器 |
| 位置参考变化率 | 位置调试模式可调；推荐初值沿用既有小幅联调的0.05 rad/s，并明确显示；原始模式不启用 | 防止待发送的大目标在首帧直接成为阶跃；显示滑条目标和实际发送参考两个数值。只调position参考，不擅自改velocity/Kp/Kd/effort的手动含义 |
| 运行位置/速度观察阈值 | 与输入范围独立，逐轴可覆盖；动作可选告警/暂停参考/结束控制 | 显示触发轴、数值、单位、阈值、所选动作；初值可沿用当前配置，行为不再隐藏 |
| 启动停稳条件 | 速度阈值及连续满足时间可编辑，默认0.02 rad/s与0ms | 等待并显示，满足后继续待启动请求 |
| 前馈范围、Kp/Kd操作范围 | 可编辑，同时显示已知的目标端能力/Mock配置上限 | 多层用同一有效配置，输入越界就地说明；删掉客户端各层重复写死的10/100/1000，保留清楚的配置默认值 |
| 短轨迹幅度/时长范围 | 范围与本次值都可设置 | 规划前说明哪个端点越界；保持手动会话，不把一次输入错误变成终止故障 |
| 停止后的观察条件 | 0.02 rad/s、100ms、最长观察时间等可见可调 | 显示“已停止发送；仍观测到运动”或“未收到反馈”；观察超时不关闭GUI |
| 录制/控制时长 | 默认直到用户结束；可主动设置定时结束 | 去掉默认写死的24小时截止；到用户设定时间时按正常结束显示 |

前馈限额始终约束最终发出的effort，而不是只约束用户偏置。辅助方式显示重力项与最终前馈，并据此前馈限额计算可用的偏置范围。若控制生成的重力加偏置超过限额，保留连续的有界输出、显示“请求值→实际发送值”，位置调试暂停参考推进；不能直接整帧不发、让看门狗再切换一遍，也不能默默删除重力项。

修改限制本身不产生运动。新范围排除了当前目标或当前反馈时，先显示冲突；不通过修改设置暗中夹到新边界并让机器人运动。

在线修改先校验，发送器确认生效版本后GUI才标“已应用”。GUI、Python和C++使用同一份有效设置；草稿与已应用设置分开。每次修改留自动事件记录，不增加观察者、备注或审核表。

### 通信设置放在高级区域

反馈接收超时（当前100ms）、模式消息超时（500ms）、模式RPC等待（3s）、GUI存活超时（2s）、记录器启动等待（10s）及客户端发送频率都显示当前值和作用。用户可在适用阶段配置；控制中不能无提示更换域号、目标端点、模型或发送频率。

前置“等待发现服务”不再和“模式RPC已发出但迟迟无回执”混用一个启动超时：前者等待并可取消；后者显示请求结果未知并结束本次启动，不自动重复RPC。

同一目标出现多个命令发布者时，启动前显示占用者并等待；运行中出现竞争则结束当前控制并明示，不能悄悄接管。

## 去除手动路径里不属于它的门禁

以下变化只作用于新手动入口：

1. 不再复用完整H1 profile校验。手动配置不要求静态窗口、拟合RMSE、起姿容差、离线跟踪包络等无关字段必须存在或为正。
2. 不再将所有错误写成同一个`terminal_fault`。等待条件、非法草稿、短轨迹输入拒绝、录制故障、软件观察越限和SDK故障分别记录；SDK故障的当前控制会话仍终止。
3. 去掉默认24小时强制结束，以及前置等待的一刀切10秒退出；保留用户主动配置的定时任务和RPC/通信失效处理。
4. 去掉客户端多处重复的力矩/增益硬编码上限，改为单一操作配置；Mock的设备限制单独保留，不与界面滑条范围混作一个数值。
5. 不引入旧`ArmFeedbackGuard`、单轴Simulator、S3/P0资格阈值来替代这些手动规则。

14轴具名顺序、有限数值、显式域号/目标绑定、模型一致性、单控制者、用户停止/关闭的进程清理继续保留；失败时明确指出哪项不符。

### 会话设置与历史记录分开

不可变连接/模型身份继续封存；可调操作策略保存为版本化设置和应用事件，不再靠编辑已封存的`protocol/profile.yaml`。旧会话按旧规则只读查看，不补写新策略。

GUI工作区、只读连接和一次控制会话分开：一次故障结束控制会话，不要求退出整个GUI或重新敲命令。后续“新建控制会话”重新读取反馈和状态，不清故障、不重放先前的目标邮箱。批量H2的故障终止规则不因此改变。

## Mock设备限制单独展示，不伪装成厂家限位

“Mock设备设置”展示接收前馈上限、重力加前馈截断、PD加前馈总请求饱和、默认PD生成规则、看门狗以及插值/驱动参数。

- 当前前馈上限100 Nm与内核总请求上限100 Nm分开命名。把内核总请求上限从默认常量透传到Mock设备配置，不再只改前馈上限而总请求仍固定100。
- Mock的1000/100增益边界来自明确的Mock能力配置，客户端不重复藏一套。厂家SDK实际不支持的输入仍应明示拒绝原因，不把Mock数值称作实机额定值。
- 修改需要重启Mock的参数只生成下一次启动配置，标明“重启后生效”；不自动重启用户正在运行的SDK服务。已应用值与待应用值分列。
- 数值积分、采样、延迟、惯量/摩擦的有效性检查保留在仿真配置层。配置不合法时列出具体字段和合法范围，在启动前修正；不往手动运动过程中搬这些门禁。
- 总请求饱和继续作为仿真驱动模型行为。GUI显示已知设备上限、实际已发送的五字段和收到的估算effort。SDK没有真实饱和标志时标为未知，不读`evaluation/plant`真值来冒充正常反馈；截断行为由独立Mock测试核验。

## 未操作轴的运动要单独解决

limit只判断范围，不能让未操作的轴自动获得重力支撑。当前首帧将14轴前馈设为0，待机支撑被撤去；这不是再加一条速度检查能修好的问题。

推荐新建GUI演练使用明确可见的“位置调试”，同时保留“原始五字段”作为直接调参方式：

- 原始方式不加隐藏补偿，五字段直接发送；界面说明未操作轴仍受动力学影响。
- 位置调试明确启用名义重力辅助，显示每轴重力项、用户附加前馈和实际发送的effort。原始方式中的effort滑条仍是直接前馈；辅助方式必须明确标成附加偏置，不暗改同一控件含义。
- 启动从新鲜反馈建立参考，再按可见的变化率转到用户目标，不将发送前拖好的目标直接阶跃下发。
- 未操作轴继续维持其目标和用户设置的增益；查看/选中另一轴不改它们的命令。保持目标不是保证实际位置完全不变，必须同时显示实际偏移。
- 运行暂停不撤掉该模式已启用的支撑；SDK故障/通信丢失则结束发送，仍按设备断流行为处理，不虚构硬件停止接口。

验证必须看未操作轴的实际反馈曲线及最大偏移，不能只拿“命令没变”证明它们没动。全部联动仍仅发双臂14轴，不填腰/头/手。

## 状态输出走统一事件，不再丢掉根因

控制状态、停止/取消和心跳通道要与录制写盘分离：录制磁盘满或文件写入失败时，仍能看到告警、接收状态并执行停止，不能连提示通道一起失效。

每个限制触发事件至少包含：中文说明、代码、阶段、轴名、实测值、阈值、单位、当前执行动作、恢复条件、接收/事件时间。一次触发保留首因，后续附加`stop_unconfirmed`等结果，不能覆盖最初的越限原因。

- 顶部固定状态条显示“只读观测 / 等待启动 / 切模式 / 发送中 / 暂停参考 / 控制已结束”。
- 轴表高亮相关轴；阈值附近显示值与单位，不只在后台日志写一个英文代码。
- 等待值持续刷新；相同事件合并显示次数与持续时间，避免逐帧刷屏。恢复时明确显示“已恢复”。
- 终端、GUI和机器记录消费同一个后端事件，GUI不另写一套判断去猜C++为什么停。
- 控制结束后只读观测继续。确实没有反馈时显示最后接收时间和“末次反馈”，不让静态模型图看起来像实时画面。
- 用户点停止只表示停止发送，正常操作不当作SDK故障；停止后的观察结果独立显示。

## 分四轮实施并逐轮交付

| 轮次 | 主要改动 | 完成条件 |
| --- | --- | --- |
| 1 可见状态与正确等待 | 发送器结构化事件、GUI持续状态/逐轴原因；拆开只读连接和控制生命周期；启动等待/取消 | 注入未停稳、无数据、服务未发现，界面有明确原因；条件恢复后仅待启动请求继续；取消后绝不稍后启动 |
| 2 统一可调策略 | 操作范围与观察阈值分离，GUI设置与应用回执，手动配置脱离H1，错误分类；先开放告警/结束控制 | 改速度输入范围不再暗改反馈阈值；各层有效设置一致；非法输入不退出GUI；不存在设置已改而实际未生效的假象 |
| 3 启动交接和保持 | 可见的位置参考过渡、显式名义重力辅助、未操作轴反馈、运行暂停/继续 | 重现本次第一轴预设目标操作；检查已发送首帧、未操作轴目标和实际反馈、前馈各项；暂停不撤支撑，原始方式仍保持直接五字段语义 |
| 4 Mock设备层与回归 | 总请求上限透传、设备设置/生效值显示、限制边界/记录故障/关闭与失联验证 | 独立检查PD加前馈饱和；所有可触发路径有可见信息；SDK故障不自动resume；原H1/H2及S1/S3/S4相关契约不变 |

“暂停参考”动作在第3轮位置参考与连续支撑实现、验证后才启用，不能先把“停止发包”改名为“暂停”。

开发和自动验证只使用私有localhost Mock，不操作现场机器人。各轮记录实际测试的轴、输入、触发值、界面状态和输出动作；不以GUI仍开着替代控制行为检查。
