# M2：ROS持续指令、频率和驱动响应验证

本轮范围是本机真实ROS通信的双端Mock。C++发端持续发布，独立C++主机端按自己的控制周期采用最新有效指令，并推进现有Pinocchio/Boost物理内核。没有另写动力学或引入MuJoCo物理计算。

这是通信测试端点，**尚不是甲方SDK或ros2_control控制器/hardware_interface适配器**。2026-10-28已审阅CASBOT02开发文档；2026-10-29取得SDK源码，确认扁平上身消息和条件化PD入口，完成六包隔离构建与17项离线契约测试。运行频率、状态原始采样时间、采用回执及力矩/电流能力仍待确认。当前接口及接入顺序见[SDK源码评估](casbot02_sdk_source_intake.md)，旧PDF和模型冲突见[原评估](casbot02_sdk_assessment.md)。后续应将这里的数据契约映射到甲方已开放的接口；其底层是否采用ros2_control尚未确认，不能同时启动另一套硬件控制循环。

## 运行

```bash
# 宿主仓库根目录；使用已有Humble distrobox。
bash scripts/humble/container.sh bash scripts/humble/build_ros.sh
bash scripts/humble/container.sh bash scripts/humble/ros.sh \
  casbot-calib ros-benchmark --config configs/ros_transport.yaml --output artifacts/my_ros_stream
# 后续重分析不启动节点，不读取evaluation参数。
bash scripts/humble/container.sh casbot-calib ros-analyse artifacts/my_ros_stream \
  --output artifacts/my_ros_stream_reanalysed
```

自动启动器只接受`scope: localhost_ros_mock`，设置`ROS_LOCALHOST_ONLY=1`、独立domain和随机私有命名空间，避免向已有机器人命令topic发送消息。整段轨迹能力未知，本轮不依赖整段下发。

Humble消息生成同时使用`Python3_EXECUTABLE`与旧`PYTHON_EXECUTABLE`；`build_ros.sh`将两者固定到系统Python，并使用系统构建工具PATH。运行/分析仍使用同版本Python创建的venv与显式ROS overlay。

## 协议与时钟

`casbot_calib_interfaces`提供三个消息：

| 消息 | 内容 |
| --- | --- |
| JointCommand | 实验/模型ID、14轴具名顺序、序号、时钟ID、发送时刻、有效时长；纯力矩或主机端软件PD模式，q/dq/前馈/Kp/Kd均为输出侧SI单位 |
| JointObservation | 采样序号与独立发布序号；采样、主机读到反馈、发布时刻；q/dq/原始电流/状态；电流派生力矩注明不是独立传感器；接受/采用/拒绝计数与超时状态 |
| CommandEvent | ROS回调接收、接受、采用、拒绝、超时事件；源/主机时钟ID和源发送/主机接收/决策/事件发布时间，客户端另记收到事件的时刻 |

Linux单调时钟ID由boot ID及time namespace构成。设备采样钟、主机钟、客户端钟分别保存，只有已声明同一时钟域才直接相减；这不是跨机同步方案。不同主机默认不报告单向指令/反馈延迟或发送至采用年龄；未映射的设备采样钟不能用于驱动拟合。客户端发送至回调事件返回的RTT可独立测量，**不除以二**。PTP/设备时钟映射后续另加，不从看似接近的时间数值猜偏移。

接收端检查实验/模型/关节顺序、模式、有限数值、合成限制、有效期和序号。已知同钟时还检查源数据年龄；未知源钟时只支持接收后的有效时长，不能声称识别了入队前的陈旧指令。旧/重复/超时/NaN输入拒绝；有效输入采用latest策略。接受后被更新输入覆盖与未到应用回调的序号分别统计。

Mock失联时撤销最后的外部力矩请求，采用名义重力及弱速度阻尼作为合成回退；在本实验的零重力条件下是弱阻尼。这个动作不是实机停止策略或位置抱持认证，真实适配必须使用设备允许的停止方式。

## 物理内核和实验矩阵

`ArmSimulationSession`是现有批量Mock的持久化内核。批量Runner和ROS端共用它；纳秒虚拟时间、Pinocchio ABA、Boost RK4、一阶电流响应、限幅、噪声和采样/驱动延迟仍共用。适配端按实际单调时间推进，只返回已到达的模拟反馈；拒绝倒退和补交过去指令。分段与批量的状态/采样/随机序列有C++对照检查。

为了隔离通信和电流响应，M2使用nominal14轴树、关闭重力的合成工况，原始惯性保留。它不替代重力/惯量标定。设备采样固定1kHz；主机控制周期、命令发布和反馈发布分别设置。

默认命令、主机控制及反馈发布统一500Hz，设备原始采样独立保持1kHz。矩阵另保留命令100/250Hz、低速反馈、显式1000Hz对照；以及软件PD、Best Effort、单CPU后台负载、rosbag录制和故障注入。正常输入QoS为Volatile/KeepLast(1)，事件诊断单独采用Reliable/深队列。故障组明确注入漏发、重复、旧序号、NaN、错误关节顺序/模式/模型及主机决策前延迟，不把注入量叫作网络故障实测。

发端按实际定时器进度选择计划点，迟到跳过而不追赶突发；计划/发送/发布均记录。主机按实际写入时刻记录全部输出请求；软件PD也先形成实际力矩请求再进入驱动。频率和时序报告使用实际记录，不以配置频率代替测量值。

## 拟合与验收

仅训练批次拟合14轴电流响应常数和写入后驱动延迟；已知输出增益2Nm/A属于合成条件。其他频率/QoS/负载/故障批次使用不同脉冲模式、冻结参数预测，不重新拟合。

驱动拟合使用**实际主机写入历史和反馈采样时刻**，两者在主机钟域；与客户端时钟是否对齐是不同问题。纳秒先减整数原点再转浮点，避免大时间戳精度损失。真实系统若拿不到写入历史/采样时刻，不能套用该方法宣称分离了网络、控制等待和驱动延迟。evaluation中的合成真值不进入拟合。

报告分开给出：

- 命令发布、回调接收、采用、控制写入、设备采样、反馈发布/接收频率及间隔分布。
- 单向可观测量、同主机决策等待、RTT的P50/P95/P99/最大值；未同步时明确不可观测。
- 发布但未在主机回调出现的序号、latest覆盖、拒绝原因、发布序号缺口和重复采样帧。序号缺口不能单独区分DDS历史覆盖、executor繁忙和网络丢包；低反馈频率跳过采样序号也不是网络丢包证据。
- 冻结电流预测误差，默认合成验收阈值1.5mA；失联检测和故障拒绝检查。
- 独立的**频率资格筛选**：接收唯一序号比例至少99%、采用频率与反馈接收频率至少达到请求值90%。这是本机带日志负载下的初步筛选，不是硬实时/实机标准。协议和模型验收通过不表示每档频率合格。

每档目前只有单批采集，不能据此推断CPU负载、录包或QoS的因果影响，也不据此推荐实机工作频率。选择工作频率前需要重复批次和随机化测试顺序；代码默认500Hz不等同于500Hz已获得实机性能认证。
