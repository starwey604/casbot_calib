## 首版交付目标与边界

首版闭环：**配置设备与模型 → C++ 七轴 Mock 采集 → 驱动尺度/时序检查 → 重力与摩擦分阶段辨识 → 多轴动态辨识 → 冻结模型独立验证 → 相同 PD 下的前馈对照 → 中文视频与参数包**。

- 原R1以固定基座右侧七轴为实现范围；新需求下左右两臂均留在整机上，固定边界在腰部抱紧夹具处，按双臂流程扩展。浮动底盘及复杂基座柔顺性仍另行处理。
- 物理模型包含构型相关惯量、科氏/离心耦合、重力、摩擦，以及既有驱动响应和通信时序。工具作为显式固定负载进入模型，首版不承诺未知工具完整惯量辨识。
- C++ 负责统一刚体计算、Mock 的机械/驱动演化和批量接口；Python 负责实验设计、时间处理、辨识、模型选择和报告。MuJoCo 只接收状态更新几何，不做正/逆动力学或接触计算。
- 首版做自由空间辨识与验证。已知接触载荷可在后续作为独立条件加入；当前不混入拨弦/鼓冲击反力，不实现复杂减速器内部、力控、安全停止或真实 SOEM/SDK。
- 同型号共用模型结构，每台臂有驱动/摩擦/几何版本及独立验收；需要时再更新刚体基参数。工具变更走负载确认/快速验证，不默认重做整臂所有参数。
- 每轮保持原 A–F、旧单关节 demo 可运行；新多轴格式显式版本化，不静默改变旧 NPZ 的形状或含义。Linux/Windows 编译与数值检查随实现逐轮加入；本机不能代替 Windows CI 的实际结果。

## 统一模型和数据契约

统一刚体与驱动关系：

`tau_rb = M(q;theta)*ddq + h(q,dq;theta) + tau_gravity(q;theta,gravity_world,base_pose)`

`tau_model = tau_rb + tau_friction(dq,T;phi)`

`diag(gain_out)*i_measured + tau_external = tau_model`

在无接触的自由空间标定中，`tau_external=0`。位置/速度/电流按已对齐的采样时刻进入辨识；力矩请求经过 PD/前馈、保持、限幅和电流响应，不能直接拿发送请求冒充实际受力。

- M、h 和重力来自同一套刚体参数；h 包含科氏/离心项，不独立拟合一个“每轴科氏常数”。转子折算惯量如使用，则以显式对角项加入一次，不能再重复包含在连杆参数中。
- 可选平滑摩擦模型为 `b*v + [fc+(fs-fc)*exp(-(abs(v)/v_stribeck)^2)]*tanh(v/v_smooth)`，其中 `b>=0`、`fs>=fc>=0`。`v_smooth` 首版固定，`v_stribeck` 与起动/低速实验的可辨识性分开检查。这是可选稳态低速代理，不宣称恢复真正的静摩擦、预滑移或滞回。
- 对惯性参数先检查可辨识基空间，保存缩放、基变换及秩，不要求逐连杆所有质量/质心/惯量唯一恢复。任意最小二乘基参数不能直接用于正动力学：需有物理可行的模型映射/受约束恢复并复验，失败就拒绝该候选。
- 估计器只接收观测、模型结构和明确先验，不能访问 Mock 的实际机械参数、ddq 或接触力真值。合成参数真值只进入评估器；名义模型与模拟设备的参数副本分开，标定不会修改正在验证的设备。

计划保留/新增的契约：

| 契约 | 计划内容 |
| --- | --- |
| ArmModel | 固定基座到七轴/工具的链、安装/重力方向、几何/惯性/工具版本及来源、关节顺序和限制 |
| DynamicsEngine | 统一正/逆动力学及重力/速度耦合/惯性分量；Mock 与前馈复用算法、使用各自冻结参数实例 |
| ArmCommand / ArmSample | 有名七轴数组、控制模式、目标 q/dq、前馈及 PD；q/dq/i、序号、逐轴状态、采样/接收时间和时钟来源 |
| 数据格式 | q/dq/current 为 N×7；命令按 N×7 分项保存；时间保持 int64 ns，同步采样与逐轴/通道偏移分别声明；不隐含所有通道同刻采样 |
| CalibrationBundle | 单机/型号/工具 ID、几何/驱动/动力学/摩擦/控制版本、尺度来源、基参数变换、适用范围、训练/验证批次及验收状态 |
| 显示 | 多轴记录只转换为已有 StateFrame；渲染读取记录/候选模型，不读取评估真值，不影响采集 |

预期落点为独立的 `cpp/include/casbot_calib/arm_*`、对应 `cpp/src/arm_*`，以及 Python 多轴采集、辨识和演示模块；原单关节路径保留。R1 已确定后端为 Pinocchio 3.9.x，由 C++ 调用 RNEA/ABA/CRBA/重力/运动学等接口；不自行实现递归刚体力学。具体模块见 [R1说明](arm_r1.md)。Linux已构建验证，双平台CI包含相同检查，Windows尚待实际执行；不能为了复用原场景而调用MuJoCo力学。

## R1：统一刚体内核与模型契约

**目标：先证明计算的是有耦合的整臂模型。**

交付：多轴模型/状态/分项力矩接口；独立可解析二连杆基准；七轴右臂配置与来源清单；C++/Python 绑定；FK 与几何显示对应关系。

验收：

- 二连杆 M、重力、非零速度耦合和逆动力学与独立解析式一致；冻结双精度测试点的归一化误差目标 `1e-8`，量纲和近零项按显式绝对容差比较。
- M 对称正定；零速度下 h=0、逆动力学零速度/零加速度分量等于重力；外加正定转子项不重复计入。
- 具有非零耦合的测试点不能被逐轴独立模型通过；不以七次标量 J 计算冒充整臂。
- 七轴链 FK 与所选几何配置一致，模型版本/轴/单位错误必须拒绝。刚体内核在不导入 MuJoCo 的情况下运行。
- 核心/绑定编译及独立数值检查接入双平台 CI，记录本机与 CI 的实际执行状态。

本轮成果以模型分量报告和七轴几何快照为主，还不是完整标定视频。

## R2：七轴 Mock、采集与时间/尺度前置检查

**目标：用统一数据格式完成真实耦合运动的采集。**

交付：C++ 多轴虚拟设备、批量 SimulationRunner、逐轴电流响应/增益/限制、纳秒调度、原始记录与独立真值、多轴回放；固定姿态保持和低幅多轴运动示例。

验收：

- 无驱动/无耗散时检查总能量；加入阻尼/摩擦后耗散；积分步长减半，轨迹和主要峰值变化小于1%。
- 复用指令/采样/接收独立调度，默认1 ms控制与1 kHz反馈；逐轴/通道时间已知与未知状态明确，丢帧不跨缺口差分。
- 当前驱动配置、增益/单位来源和几何版本固化为会话；未经声明的变化拒绝继续；PD 使用的是可获得的关节量，设备响应与反馈噪声另行建模。
- 所有 g_out 先验有 `synthetic_declared`、独立校验或 `unanchored` 等来源状态。未锚定时禁止宣称绝对惯性/力矩标定通过。单关节 B 的附加惯量方法不能未经推导直接推广为七轴增益恢复。
- 在未做七轴已知负载尺度实验前，演示使用明确声明的合成增益先验；这只验证后续辨识流程，不宣称完成实机七轴驱动尺度标定。
- 七轴原始记录可由无 MuJoCo 程序生成，渲染只重放；生成首个整臂运动预览，原始数据不覆盖。

## R3：重力 → 摩擦 → 动态参数标定

**目标：形成首个无 GUI 可运行的整臂标定闭环。**

| 子步骤 | 实验 | 估计对象与限制 |
| --- | --- | --- |
| 3A 重力 | 多构型准静态/保持，包含不同方向接近与稳定区段 | 在已知安装方向和几何版本下，辨识可观测的质量一阶矩/基参数组合；考虑静摩擦偏差，不把静态数据当作全惯量辨识。 |
| 3B 摩擦 | 各轴正反向、多速度、低速区段；其他轴固定，必要时多构型复验 | 用重力补偿后的有效区段估计 b/fc，可选 fs/v_stribeck；加减速、饱和、缺帧区段按条件处理。缺激励的低速参数固定或报告不可辨识。 |
| 3C 动态 | 多关节有耦合的周期多频运动，保持轨迹/力矩/速度/加速度约束 | 对实际 q 做傅里叶拟合并解析求导，建立多轴力矩回归；对同一模型的惯性/重力基参数及必要摩擦作受约束细化。 |
| 3D 模型交接 | 整条独立轨迹/构型批次 | 冻结参数、尺度和处理流程，验证后输出候选包；重力/摩擦分阶段结果不是互不相容的多套完整逆动力学。 |

PD+名义前馈可以用于激励，但实验必须记录其闭环属性；约束/鲁棒损失不自动解决测量误差偏差。用独立噪声/轨迹验证偏差，保留之后引入 IV 等方法的入口，首版不声称闭环无偏。

验收：

- 参数/基空间和预测残差有明确版本；单轴/单频或不足构型的负例报告秩不足/适用范围，不能输出看似完整的逐连杆参数。
- 在合成且模型匹配的基准中，以逐轴独立力矩预测为主；不强求不可辨识原始参数逐项等于真值。初始目标：无噪声逐轴归一化 RMSE≤1%；公布噪声配置下10批至少9批逐轴≤5%。
- 归一化定义为 `rms(residual_j)/max(rms(observed_torque_j), torque_floor_j)`，逐轴力矩下限在实验前配置并保存，同时报告绝对Nm残差。数值门槛只用于合成配置，执行前连同轨迹/频带/噪声固化；不能掩盖低激励轴。
- 输出奇异值、基映射、有效姿态/速度/温度范围、重力/摩擦/动态残差与整批重复性。训练集筛选/调参不能使用独立验证的分数；若验证失败，再调整后必须另采新的验证批次。
- 删除评估真值后，估计和观测报告仍能运行；原始数据及模型/配置摘要在处理前后保持一致。

## R4：冻结模型、前馈消融和独立任务验证

**目标：证明标定模型带来控制收益，并暴露适用边界。**

交付：保持相同设备、初态、控制周期、PD、限制和独立轨迹的以下对照：

1. 纯 PD，无模型前馈。
2. PD + 重力。
3. PD + 重力 + 摩擦。
4. PD + 名义完整逆动力学。
5. PD + 标定后完整逆动力学。
6. 标定模型去掉速度耦合项的负对照，用来检验对应动作是否需要该项。

先固定 PD 比较模型与分项贡献；需要调参时再使用独立选择轨迹，避免把 PD 的改善记在标定收益中。前馈参考状态/目标加速度的使用约定需固定，各对照不能偷偷换成不同控制律。

验收：

- 按逐轴 q/速度/电流及基于同一几何模型的名义末端轨迹列报；名义 FK 误差不称为外测绝对定位精度。
- 检查速度、力矩、饱和、跟踪 RMSE/峰值、终点过冲及稳定时间。整臂汇总指标须声明权重，同时保留逐轴结果，不能平均掉某一轴严重退化。
- 合成基准拟采用“标定完整前馈相对纯PD的汇总归一化RMSE降低至少20%”作为演示门槛；限幅与任务约束保持一致。实际阈值在基准配置运行前固化，不宣称每种负载、速度或每个关节都必然改善。
- 冻结同一模型验证1/2/4 ms控制周期（默认反馈1 kHz）、独立噪声种子和多个未用于训练/选择的构型/轨迹。需要新负载包的工况明确标记，不能静默重新拟合。
- 公布分量计算、批量模拟和求解耗时；没有目标控制器的整周期数据时，DYN-4保持待验，不把桌面机平均性能标为1 kHz产品通过。

## R5：中文整臂标定视频与可复查交付

**目标：形成类似现有单关节视频的整臂过程演示。**

八个阶段：**设备/模型检查 → 重力采集 → 正反向摩擦 → 多轴动态激励 → 辨识与可辨识性 → 冻结模型验证 → 前馈前后对照 → 参数包交接**。预计一分钟左右，时长按真实记录调整，不作为验收指标。

画面使用整臂几何、自动选中的肩/肘/腕、逐轴曲线、预测/电流派生力矩及分项贡献、独立误差和适用范围。界面指标来自观测/候选模型；真值另存评估，默认演示不读取真值。训练与独立验证分批回放，明确回放倍率和阶段切换，不伪装在线实时辨识。

交付：

- 可独立运行的整臂配置、采集/标定/验证/重渲染入口，以及旧单关节实验回归结果。
- NPZ原始记录、JSON/CSV参数与指标、PNG曲线、中文H.264视频、场景/模型与数据摘要、失败日志。
- 标定包记录型号/序列号/工具、几何/驱动/模型/控制版本、来源状态、基参数映射、适用范围与验证批次；只把合成通过的候选标为合成候选。
- Linux/Windows核心构建和完整数值实验结果；可选渲染按平台记录实际验证情况。视频和大量采集产物沿用gitignore；确需版本化的大资产另按LFS管理。
- 渲染前后核对数据/候选摘要，禁止任何MuJoCo动力学API；同一已归一化遥测接口可继续用于未来实机只读显示。

| R3 | 分阶段标定与独立预测CLI | 一个完整标定候选、基参数/残差/不可辨识负例 |
| R4 | 冻结验证、六组前馈对照、周期/重复性实验 | 逐轴和整臂控制报告、收益和失败边界 |
| R5 | 中文渲染与可复查交付 | 整臂标定视频、报告、配置和参数包 |

轮次是实现与交付边界，不承诺固定日期或一次对话内完成；任何一轮尚有失败验收项就记录并修复，不跳过门槛完成演示。每轮有最小可运行入口，避免直到最后才联调。

原单臂计划的延期项包括真实EtherCAT/SDK与时钟映射、驱动尺度实测、未知工具惯量快速辨识、传动柔度/背隙、温漂实测、鼓击打与接触及浮动底盘。双臂现已纳入当前产品目标，具体实机接入顺序和轨迹约束以新流程为准；这些能力均不能因写入计划就标为已实现。
