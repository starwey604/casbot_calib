# SDK实机接入前必须确认的能力

**本清单是实机接入与启用标定流程前必须逐项弄清的前置条件。** 每项须绑定证据；未知项继续标为未知，不得用SDK字段存在、客户端编译成功或Mock验收通过代替设备能力确认。设备身份（序列号／固件／运控版本）按2026-11-09用户授权暂不列为门禁，见[现场条件](#现场条件与接口可读性2026-11-09-用户确认)。确认“不支持”也是有效结论，但必须阻断或重新设计依赖它的阶段。

当前S1只读接口、S2本机位置流程、S3观测资格和S4离线闭环已经实现；**实机运动、物理网络性能、真实力矩控制和现场标定尚未验收**。S2的localhost限制保持。本文是后续联调的能力清单，不会自动开放实机执行或修改保护。

2026-10-30用户进一步要求先写完硬件路径，不确定行为可用明确假设联调。新增[硬件现场入口](hardware_execution_path.md)支持真实SDK位置流和静态探索；本清单继续约束正式观测/标定资格，不阻断其余实现。用户确认只发双臂14轴时腰/头/手保持；断流后机体自保护按用户要求先作假设，需到场验证。异常停止发布并记录是否收到静止反馈，不虚构厂商stop服务或物理停止证明。原S1/S2/S3/S4契约和保护不直接改值绕过，现场路径另存profile及假设，探索候选不自动部署。

H2询问了“断流保护后能否直接重新申请上身调试，还是须清故障”，当前未取得厂家答案。用户明确指定：先预留默认clear_fault API，只log、留空，随后结束整个采集流程；以后再探索恢复。因此[H2](hardware_batch_h2.md)当前不自动恢复、不重新申请控制，不允许故障会话resume；正常检查点/受控主动中断的续采与静态质量重采独立处理。本条是用户的软件行为要求，不是厂家已提供清故障接口的声明。

SDK Mock收敛时另询问了position插值的起终点、窗口以及time_ref=0语义。用户要求先按最简单线性插值实现；[统一Mock](sdk_mock_unification.md)因此采用当前参考到最新目标的可配置固定时长线性过渡，默认2ms。time_ref=0取自SDK上身示例，不代表厂家确认了2ms窗口，其单位和实际消费仍待确认。

只读采集是确认能力的一种手段：核对连接和具名位置反馈后，可在任务授权范围内使用S1订阅，不发布命令或切换模式；effort、时钟等未知字段保留未知。只读采集成功不授予位置运动或动力学标定资格。

### 对采集与标定流程的影响

- 保留原始消息、发布stamp和本地单调接收时刻，分别标注事件/钟域；没有实际采样时刻、新帧序号及缓存年龄时继续保留未知。重复发布也保留为原始记录，不能把数值相同直接判为旧帧或删除：静止时的新采样也可能相同。
- 频率分档仍以客户端100/250/500Hz发送为计划，默认500Hz；厂家的1000Hz位置插值及debug反馈发布是另外两层频率，尚未实测。可报告实际发送/接收频率、发布节奏（stamp钟域明确后）、到达抖动和整体运动响应，不能据此给出电机采样率、新帧更新率、网络丢包率或拆分出的单向延迟。RTT不除以二。
- 不按发布stamp直接对缓存位置差分求速度/加速度，也不把位置插值参考的导数当作实际运动。缓存跳变会污染导数；仅去重或低通不构成采样资格。现有ZOH加一阶电流响应实验不能直接解释这条位置插值、估算力矩反馈链路。
- 质量/质心的静态重力实验可优先准备：等待稳定、核对窗口内确有反馈刷新，明确力矩尺度/零偏、状态和静摩擦影响。重复缓存不算独立样本，延长等待不能证明数据新鲜。**当前S3重力资格仍要求合格采样时刻等证据，此类仅含发布时刻的记录不会自动通过；若采用静态缓存替代观测，须另行实现并验证协议。**

- 长匀速段的运动摩擦可作为后续替代观测方案研究，需验证真实速度、加速度、刷新情况和力矩含义；目前不获得现有动态入口资格。起动摩擦受运动/力矩缓存年龄差影响，惯量受加速度/力矩相位影响，当前反馈信息不足以精确验收。低频周期拟合也不能自行消除未知缓存年龄、异步或滤波误差。
- 保留现有4kHz动态及摩擦独立更密采样政策和历史Mock回归；它们是当前方法的资格边界，不是厂家通用采样指标。不能将4kHz直接改成1000Hz或把未知滤波标为无滤波。新SDK观测路径须独立验证并使用新协议/数据，不回写旧证据，也不以本次说明解锁S2实机执行。

静态姿态的离线准备可用[现场扫描预设](static_field_preset.md)：具名相对角度扫描、重力信息选点及正反进退参考碰撞检查。它只生成参考和角色，不采集数据、不替代上述资格，也不开放实机。

### 「腰部抱死时的驱动设置」指什么

现场为双臂标定用机械夹具把腰部固定（抱死），而SDK的上身／全身命令通道覆盖腰、头、手。用户确认只发双臂14轴后，这些**未指定的轴由谁、以什么方式保持**就成了必须先弄清的问题：驱动器是保持原目标／力矩、释放、被当作缺省值0，还是因为机械上动不了而积分饱和、持续出力甚至报故障？它同时牵涉「未指定轴行为」（SDK-02）和「夹具与安装条件」（SDK-10）。现场可先用只读方式观察腰部反馈是否稳定、有无故障记录或异常effort，再向厂家确认驱动配置；在此之前不假定保持、不向腰部填目标或增益，也不把「只发14轴」理解成腰部已被证明处于安全状态。

程序侧落点：`configs/hardware_field.yaml`的`assumptions.arm_subset`（`user_confirmed_14_arm_axes_leave_waist_head_hands_unchanged`）与`assumptions.mode_first_frame`（`user_confirmed_hold_prior_target_output_until_first_valid_command`）已按「保持原目标／输出」写死；`hardware_field.py:32`只校验这两个字符串精确匹配，不校验物理行为，属于配置声明而非设备能力确认。若实测为「释放」或「缺省值0」，该前提不成立且现有执行器不会自行察觉：`vendor_data.py:13`要求恰好14个具名轴，规范化只取14轴子集，非目标轴的位移不会进入起点稳定判定、碰撞检查、重力前馈或静态力矩拟合；`UpperJointData.msg`的`string[] name`只声明命令携带哪些轴，未声明服务端对未列入轴的处理，`mode_first_frame`约定也只覆盖切入到首帧之前、不覆盖首帧之后每帧的未列入轴。因此区分三者须在14轴规范化路径之外，额外保留完整原始CDR与全轴`name`数组，分别观察模式切入前后、首条`joint_cmd`前后、断流前后；原始`packets.jsonl`虽有全量字段，但规范化产物不含非目标轴，不能用规范化记录代替该证据。

## 因克斯模组本地PD能力证据

2026-10-30核对到以下公开资料：

- 因克斯署名的[电机数据手册，PDF第2页](https://www.worldrobotconference.com/uploads/exuser2024/video/8kgvba.pdf)说明模组集成电机、减速器及驱动器，支持力位混控、位置、速度、电流（力矩）等模式。该资料证明产品模式能力，不是CASBOT当前固件的接口验收。
- 原驱动作者的[ENCOS驱动源码，固定提交60f5a21](https://github.com/THMOS2025/encos-driver/blob/60f5a215c02ebe354bf3c4054abc02f25e580b63/src/encos_command.c#L67)将Kp、Kd、目标位置、目标速度、目标力矩直接打包成CAN控制帧；对应[实现说明](https://wegg111.github.io/mos9-website/communication/motor_communication/)展示五类输入。该发送路径没有先用ROS反馈在客户端算成单个PD力矩。

两者支持采用模组本地力位混控/PD的建模选择。控制形式可称MIT式；不能据此认定CAN字节协议与标准MIT协议相同，或所有型号/固件增益单位、限幅均相同。**用户随后明确确认：CASBOT主机直接转发position、velocity、kp、kd、effort五项，由因克斯模组以本地反馈计算PD。该转发与执行位置固定为本项目接口约定，不再列为未知或重复询问。** position仍按此前说明由主机线性插值到1000Hz参考，然后与另外四项交给模组；不能把“转发五项”理解为取消该插值。PD实际运行频率、具体编码器来源仍待核验；1000Hz位置插值不等于已知PD环频率。

SDK Mock默认device_pd=true，由现有机械内核以本地状态计算PD；网络影响参考/前馈送达及反馈观测，不把ROS反馈回传延迟额外插入本地PD。此执行位置采用上述用户确认，正式采样/尺度资格不自动升级。控制律为τ=Kp(qref−q)+Kd(vref−v)+effort；本次用户确认effort相加、零PD有效及无主机自动重力/摩擦，其余限幅/驱动响应仍分别记录。

用户已确认的控制关系如下，由模组本地执行；限幅位置和具体数值仍需核验：

\[
\tau_{\mathrm{out}}=K_p(q_{\mathrm{ref}}-q)+K_d(\dot q_{\mathrm{ref}}-\dot q)+\tau_{\mathrm{effort}}+\tau_{\mathrm{internal}}
\]

H3用户确认的主机约定对应上述PD+effort，内部重力/摩擦项为0；各项限幅位置和反馈覆盖范围仍待核验。若反馈已是可信总输出Nm，可直接接S3，不强求反算电流；电流换算力矩仍不是独立力传感器，也不要求为了流程成立额外安装力传感器。

## 各阶段开放条件

所有运动阶段先满足连接、实际起始姿态、轴映射、设备限制、模式/停止、腰部固定和真实几何的共同条件。实际方向验证只能在这些条件具备后执行；既有Mock方向/软件零位检查不证明机械零位。

| 工作 | 额外能力条件 |
| --- | --- |
| 只读记录/显示 | 核对具名位置和单位/模型映射，保持订阅；其余字段允许未知并如实记录，不授予标定/运动资格 |
| 位置轨迹及后续TriCal运动 | 上身位置命令、未指定轴/腰部行为、实际模式和停止路径明确；TriCal另需真实量具/工装计量 |
| 重力 | 可信总输出力矩、尺度/零偏、补偿含义、稳定窗口和合格时刻/状态；不必具备纯力矩控制 |
| 运动摩擦 | 前序通过；真实匀速/加速度、原始动态带宽/滤波/时钟及独立更密采样收敛成立 |
| 起动摩擦 | 前序通过；可施加已知重力补偿力矩斜坡，零PD/补偿语义明确，主机反馈保护和停止成立 |
| 惯量 | 前序冻结且通过；可信动态力矩、实际轨迹/时刻、合格周期激励及双腕独立探测；位置激励可用，不必先具备纯力矩控制 |
| 前馈/PD控制对照 | command effort叠加和补偿开关已确认、增益真实生效、限制一致；选择与验收轨迹分开 |

当前软件政策中，动态原始观测门槛为4kHz，运动摩擦还要求独立更密采样对照，腕部处理须覆盖30Hz频带。这些是本项目现有方法的资格边界，不是厂家通用指标，也不要求ROS必须以4kHz发布；可用主机原始日志。低频周期平均等替代观测需另做独立验证，不能直接降阈值。详见[S3](vendor_s3.md)、[S4](vendor_s4.md)。
