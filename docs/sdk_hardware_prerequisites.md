# SDK实机接入前必须确认的能力

**本清单是实机接入与启用标定流程前必须逐项弄清的前置条件。** 每项须绑定具体机器人、运控/固件版本和证据；未知项继续标为未知，不得用SDK字段存在、客户端编译成功或Mock验收通过代替设备能力确认。确认“不支持”也是有效结论，但必须阻断或重新设计依赖它的阶段。

当前S1只读接口、S2本机位置流程、S3观测资格和S4离线闭环已经实现；**实机运动、物理网络性能、真实力矩控制和现场标定尚未验收**。S2的localhost限制保持。本文是后续联调的能力清单，不会自动开放实机执行或修改保护。

2026-10-30用户进一步要求先写完硬件路径，不确定行为可用明确假设联调。新增[硬件现场入口](hardware_execution_path.md)支持真实SDK位置流和静态探索；本清单继续约束正式观测/标定资格，不阻断其余实现。用户确认只发双臂14轴时腰/头/手保持；断流后机体自保护按用户要求先作假设，需到场验证。异常停止发布并记录是否收到静止反馈，不虚构厂商stop服务或物理停止证明。原S1/S2/S3/S4契约和保护不直接改值绕过，现场路径另存profile及假设，探索候选不自动部署。

只读采集是确认能力的一种手段：核对连接和具名位置反馈后，可在任务授权范围内使用S1订阅，不发布命令或切换模式；effort、时钟等未知字段保留未知。只读采集成功不授予位置运动或动力学标定资格。

### 对采集与标定流程的影响

- 保留原始消息、发布stamp和本地单调接收时刻，分别标注事件/钟域；没有实际采样时刻、新帧序号及缓存年龄时继续保留未知。重复发布也保留为原始记录，不能把数值相同直接判为旧帧或删除：静止时的新采样也可能相同。
- 频率分档仍以客户端100/250/500Hz发送为计划，默认500Hz；厂家的1000Hz位置插值及debug反馈发布是另外两层频率，尚未实测。可报告实际发送/接收频率、发布节奏（stamp钟域明确后）、到达抖动和整体运动响应，不能据此给出电机采样率、新帧更新率、网络丢包率或拆分出的单向延迟。RTT不除以二。
- 不按发布stamp直接对缓存位置差分求速度/加速度，也不把位置插值参考的导数当作实际运动。缓存跳变会污染导数；仅去重或低通不构成采样资格。现有ZOH加一阶电流响应实验不能直接解释这条位置插值、估算力矩反馈链路。
- 质量/质心的静态重力实验可优先准备：等待稳定、核对窗口内确有反馈刷新，明确力矩尺度/零偏、状态和静摩擦影响。重复缓存不算独立样本，延长等待不能证明数据新鲜。**当前S3重力资格仍要求合格采样时刻等证据，此类仅含发布时刻的记录不会自动通过；若采用静态缓存替代观测，须另行实现并验证协议。**

- 长匀速段的运动摩擦可作为后续替代观测方案研究，需验证真实速度、加速度、刷新情况和力矩含义；目前不获得现有动态入口资格。起动摩擦受运动/力矩缓存年龄差影响，惯量受加速度/力矩相位影响，当前反馈信息不足以精确验收。低频周期拟合也不能自行消除未知缓存年龄、异步或滤波误差。
- 保留现有4kHz动态及摩擦独立更密采样政策和历史Mock回归；它们是当前方法的资格边界，不是厂家通用采样指标。不能将4kHz直接改成1000Hz或把未知滤波标为无滤波。新SDK观测路径须独立验证并使用新协议/数据，不回写旧证据，也不以本次说明解锁S2实机执行。

静态姿态的离线准备可用[现场扫描预设](static_field_preset.md)：具名相对角度扫描、重力信息选点及正反进退参考碰撞检查。它只生成参考和角色，不采集数据、不替代上述资格，也不开放实机。

### 下一步最有价值的补充信息

优先请厂家提供每轴实际收到新模组反馈时更新的序号和时间戳（或缓存更新时间/数据年龄），缓存重复发布时保留原序号/时刻；说明q/dq/effort是否来自同一帧、各轴是否同步。若只能取得主机接收模组反馈的时刻，须明确其事件含义：可辅助识别刷新和缓存，但仍不能冒充电机采样时刻。其次补齐具体设备/版本、effort侧别/尺度/滤波与总输出含义、position插值及其他命令字段的实际消费规则。当前没有可用高频日志时，按未提供记录，不把日志接口定义当作日志能力。

**最高优先级是SDK-03至06：反馈effort到底是什么、指令effort到底怎样执行。** 同时，任何现场运动都以SDK-02、09、10及相应连接/时序条件闭合为前提。

需要甲方确认的候选控制关系为：

\[
\tau_{\mathrm{out}}=K_p(q_{\mathrm{ref}}-q)+K_d(\dot q_{\mathrm{ref}}-\dot q)+\tau_{\mathrm{effort}}+\tau_{\mathrm{internal}}
\]

这不是对现有主机实现的断言。必须说明每一项的单位、开关、限幅位置，以及反馈effort覆盖了哪些项。若反馈已是可信总输出Nm，可直接接S3，不强求反算电流；电流换算力矩仍不是独立力传感器，也不要求为了流程成立额外安装力传感器。

## 各阶段开放条件

所有运动阶段先满足连接、实际起始姿态、轴映射、设备限制、模式/停止、腰部固定和真实几何的共同条件。实际方向验证只能在这些条件具备后执行；既有Mock方向/软件零位检查不证明机械零位。

| 工作 | 额外能力条件 |
| --- | --- |
| 只读记录/显示 | 核对具名位置和单位/模型映射，保持订阅；其余字段允许未知并如实记录，不授予标定/运动资格 |
| 位置轨迹及后续TriCal运动 | 上身位置命令、未指定轴/腰部行为、实际模式和停止路径明确；TriCal另需真实量具/工装计量 |
| 重力 | 可信总输出力矩、尺度/零偏、补偿含义、稳定窗口和合格时刻/状态；不必具备纯力矩控制 |
| 运动摩擦 | 前序通过；真实匀速/加速度、原始动态带宽/滤波/时钟及独立更密采样收敛成立 |
| 起动摩擦 | 前序通过；可施加已知重力补偿力矩斜坡，零PD/补偿语义明确，主机反馈保护和停止成立 |
| 惯量 | 前序冻结且通过；可信动态力矩、实际轨迹/时刻、合格周期激励及双腕独立探测；位置激励可用，不必先具备纯力矩控制 |
| 前馈/PD控制对照 | command effort叠加和补偿开关已确认、增益真实生效、限制一致；选择与验收轨迹分开 |

当前软件政策中，动态原始观测门槛为4kHz，运动摩擦还要求独立更密采样对照，腕部处理须覆盖30Hz频带。这些是本项目现有方法的资格边界，不是厂家通用指标，也不要求ROS必须以4kHz发布；可用主机原始日志。低频周期平均等替代观测需另做独立验证，不能直接降阈值。详见[S3](vendor_s3.md)、[S4](vendor_s4.md)。

## 如何记录确认结果

每项建立如下记录并关联实机数据契约：

| 字段 | 内容 |
| --- | --- |
| item_id / status | 上述编号；待确认、已说明待验证、已验证或明确不支持 |
| device / versions | 序列号、型号、运控/固件/消息版本、实际模型和安装/负载身份 |
| conclusion / scope | 明确能力、单位/方程/限制，以及适用模式和阶段 |
| evidence | 对应代码/配置/书面说明及试验日志的路径、版本和摘要；注明证据是声明还是测量 |
| verification | 核验方法、实际结果、未决项、责任人/日期；不只填写一个passed布尔值 |

先取得版本/代码/配置与只读资料，再在已经具备运动前提的范围内验证；不能用尚未确认的零PD、停止或力矩命令来试探其是否可用。设备、固件、控制配置、模型、负载或安装变化后，重核受影响项。

未决项按阶段阻断；已说明但尚未验证不记为实机已验证。不得直接把S1的unknown改成已知来绕过检查，不得移除S2 localhost限制作为接入捷径，不得把S4的Mock收益或复用开发验证写成现场最终验收。
