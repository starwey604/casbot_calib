# K2：双臂千分计Mock、碰撞门禁与自动对中

本轮承接[K1–K5计划](kinematics_trical_plan.md)，先提交K1（`c2d2e6e`），再实现K2。当前是腰部固定、完整14轴nominal双臂的离线合成测量流程；没有实机、SDK、ROS仪表适配或几何参数辨识。MuJoCo未参与任何机械计算，本轮不新增视频，K4再接只读演示。

后续[K3](kinematics_trical_k3.md)在本测量层上增加六球选点与几何辨识；下面的四球条件与历史验证数值仍专指K2，不作为K3完整几何可辨识性的依据。

## 可运行入口

主环境为[Humble](humble_environment.md)，没有新增依赖。输出目录须不存在，不支持覆盖旧会话或自动续跑：

```bash
# 四个固定球，左右臂顺序各测两个；完整对中和退出
bash scripts/humble/container.sh casbot-calib trical-mock \
  --config configs/kinematics_trical_mock.yaml --output artifacts/my_trical
# 可只验证第一个测点，或注入指定仪表故障（故障实验应返回非零退出码）
bash scripts/humble/container.sh casbot-calib trical-mock \
  --first-only --fault disconnected --output artifacts/my_trical_disconnected
# 仅从已保存观测重验稳定窗口和碰撞门禁，不读取evaluation
bash scripts/humble/container.sh casbot-calib trical-analyse artifacts/my_trical \
  --output artifacts/my_trical_analysis
# 完整K2验收：双臂、故障、未知时间、碰撞拒绝、真值隔离与中文读数图
bash scripts/humble/container.sh casbot-calib trical-suite --output artifacts/my_trical_suite
```

不传`--config`时从随包[合成profile](../python/casbot_calib/assets/trical_workflow_v1.json)加载，独立wheel不依赖当前目录下的configs文件。YAML只选择profile和命令周期；默认2ms/500Hz。三表每通道50Hz、关节原始采样1kHz、物理RK4最大50µs是独立设置，不把500Hz当成仪表能力。

## C++设备Mock

[trical_mock.*](../cpp/include/casbot_calib/trical_mock.hpp)的`TricalMockSession`包装现有持久化`ArmSimulationSession`，没有复制动力学或积分实现。Pinocchio计算实际模拟状态下的测量TCP，C++仪表模型产生读数；`advance_to()`计算期间释放GIL，没有逐积分步Python回调。实例为单一所有者，不能并发推进/修改。

- 三通道独立序号和相位：0/1/2ms，周期20ms。当前事件必须在关节原始采样网格上，非整齐网格配置直接拒绝，不能隐式拿较近采样冒充真实采样时刻。
- 默认反馈延迟3ms、抖动±0.5ms、噪声标准差1µm、量化1µm；可设置丢帧、无采样时间、偏置和有限测头接触面。均为合成条件。
- 模拟测头是平面圆形有效区域，碰撞代理用包住该面的方形薄片。仅当球的接触投影落在有效面内且行程/读数在量程内才标VALID；无接触、超量程、失联、冻结分别保留状态。冻结从启动时也生效，保留旧序号/采样时刻并刷新接收时刻。
- 指定目标携带工具名和球ID；切换目标不把在途旧包当作新目标反馈。控制器只能消费已经送达的包。
- 隐藏编码器偏置满足`q_physical = q_observed + offset`，指令目标也在同一编码器坐标中解释。偏置不写入操作模型，控制器只用名义几何和读表修正。
- `retain_truth=False`时不输出评估真值，但仪表仍由内部实际状态产生。启用评估时真值单独写入`evaluation/`，不进入控制器读表、IK、对中或稳定窗口判断。

本轮仪表是忽略载荷的理想几何探测，不产生接触力、工具质量或复杂表杆机械过程。测头碰撞对象为固定薄片代理，对选定球允许有界重叠，尚未描述真实测杆伸缩后的占据体积；因此证书仅适用于当前声明的代理场景。接实物前必须用实际工具及测杆全行程包络替换该模型，重新验证与支杆/表架的间隙。其位置误差不能作为真实受力条件下的几何精度，实物工具质量/质心、预紧及挠度也要另行确认。

## 工装与碰撞约束

K1工具仅用于接口校验，尺寸不能直接用于接触运动。K2明确采用掌部局部Z方向+280mm的合成工具，测量点位于固定手部包络之外；包括表架、连接件、三个有限测头。四个球及其支杆均为固定世界几何，左右两组在同一个有尺度的基准体系中，**不是每条轨迹重新定义球坐标**。

四球配置源于公开的名义任务姿态设计，没有使用隐藏编码器偏置把测量数据预先对中。K2左右臂各测两个球，只验收测量闭环。它不保证足以辨识全部几何参数，K3再选取多个工具朝向和冗余构型。

[trical_fixture.py](../python/casbot_calib/trical_fixture.py)继续使用审计过的机器人凸包缓存，添加球、支杆、表架、连接件和测头。球用**外包**凸多面体，避免低估球占据范围。Coal做距离查询，Pinocchio放置几何：

1. 非接触阶段全部活动碰撞对保留10mm余量，包括另一臂、腰部夹具代理、全部工装与非目标球。
2. 插入、对中和退出阶段，仅允许当前工具的三个具名测头与当前球使用有界行程接触，最小代理表面距离为-5mm。三对关系逐项存储和摘要，不排除球架、整只手或所有工具/球接触。
3. 对支杆、表架和其他球仍要求正的10mm余量。相同刚体parent内的固定装配几何沿用原有分组；这不证明实际握持安装或工装强度。
4. 完整接近→插入→退出→回位在开始运动前预检；每次闭环修正还要预检其退出路径，失败不能继续靠近。
5. 参考曲线沿用septic Hermite/Bernstein，限制速度、加速度和jerk；连续区间使用运动界，未决细分拒绝。20ms批量反馈边界检查已送达位置的Coal距离与不确定性包络；每段结束后再验证观测折线路径和最大采样间隔。

当前合成编码器/观测误差包络为每轴±1.05mrad，Mock工厂核对隐藏偏置加6倍位置噪声不超过该范围。包络进入参考、在线已送达位置和观测折线门禁，也检查不确定位置不超关节限位。它不是实际机器装配误差承诺，不能用来接受毫米级任意几何变形。位移计有效面半径2mm、±5mm行程、工具尺寸均为合成配置。

原低位球架曾因肘/腕经过腰部夹具被拒绝，记录保留在`artifacts/kinematics_k2_layout_rejected`。旧第四测点的修正退出包络也曾拒绝，保留在`artifacts/kinematics_k2_v1`；后续用另一公开名义任务姿态重新设计第四球的位置，未降低10mm余量或对中阈值。当前四球布局是`synthetic_four_ball_k2_v2`。

负的“最小表面距离”或“区间距离下界”只可能用于审计过的接触对，不能与全局10mm直接比较。判断应按每对阈值与几何包络完成，而不是查看一个全局最小距离。观测证书只覆盖声明的关节折线插值，不证明未观测实机运动；20ms反馈检查也不属于硬实时防碰撞功能。

## 自动对中状态机

[trical_workflow.py](../python/casbot_calib/trical_workflow.py)驱动以下步骤：

```text
选择具名工具/基准球 → 完整路径预检 → 低速接近 → 插入
→ 等待稳定 → 读取三个独立通道 → 有界笛卡尔修正
→ 重新验退出路径 → 修正并保持 → 重复读表
→ 稳定窗口通过且偏差≤30µm → 保存测量 → 退出 → 回位
```

名义任务IK使用Pinocchio FK和SciPy；局部修正使用具名TCP的Pinocchio雅可比和阻尼最小二乘。每次最多1.5mm笛卡尔修正、每轴0.02rad，之后仍由完整轨迹/碰撞门禁判定是否可以执行。

**修正累积到上一轮指令目标，雅可比在实际观测角度计算。** 直接用观测角度替代目标会在每轮重引入伺服静差；开发时已用右臂反例确认该问题，没有通过放宽30µm阈值处理。

稳定窗口默认140ms、至少6个三通道新样本，要求各通道序号严格递增，全部VALID，关节/仪表反馈不过期，关节速度、角度变化和表读数变化均低于设定值。窗口用实际观测，不用指令静止冒充实际稳定；读数均值保留残差，不改写成零。

未知仪表采样时刻保持-1。只允许在声明的Mock投递年龄上界和更长的静止保持后做静态窗口判断，不声称已同步，也不把接收时刻当采样时刻。真实仪表若不能给出时间或缓冲年龄能力，需要在K5重新制定接受条件。

失联、超量程、冻结、反馈超时、不稳定/不收敛或碰撞门禁失败均拒绝采样。具备有效关节反馈且退出路径通过时保持并退回；否则锁存保持并记录`latched_hold_manual_recovery_required`，不盲目自动回位。未连接实机，此行为不代表实际急停或安全认证。

Python按20ms决策批次计算并提交2ms网格指令；Mock按虚拟时间推进，**不等待墙上时间**。将来真实适配层需由本地发送器持续发布500Hz ROS消息，不要求机器人支持整段轨迹上传。该轮没有接入物理ROS以太网，也不替代原有频率/延迟预检。

## 原始记录、复核与交付

- `profile.json`/`geometry.json`：操作模型、工装、单位和能力配置；不含`mock`隐藏偏置。
- `raw/joint_packets.npz`、`indicator_packets.npz`、`commands.npz`：原始包、通道状态和实际提交的指令；仪表包保留各自采样/接收时间。
- `journal/`：每约1s写入新的只读采集片段，进程中断时保留已落盘数据。未形成最终manifest的目录不能当作已完成会话；本轮不实现resume。
- `observations/`：沿用K1三表记录格式，包含独立通道状态、时钟与关联的14轴实际观测。行是关联快照，不假定同时采样。
- `events.json`、`motions.json`、`measurements.json`：状态转移、连续参考/观测证书、在线距离检查计数、采样窗口索引和非零对中残差。
- `manifest.json`：操作数据及配置的SHA256；不将`evaluation/`加入重分析输入。原始数据不可覆盖，失败会话保留拒绝原因和退出轨迹。
- `evaluation/`：隐藏偏置及实际物理状态，只供独立合成评分。

`trical-analyse`检查摘要、500Hz实际指令时间网格，从原始数据重新判定稳定窗口，重算参考及观测碰撞门禁，不读取评估真值。完整suite会先把整个evaluation目录移到会话之外，再运行该复核并确认原始文件没有改变。

完整suite还独立运行：仪表失联、冻结、超量程、无接触、全部读数丢失、未知采样时刻，以及目标处新增障碍的预检拒绝。前五种故障应无有效测量且按条件退出；未知时刻只在静态能力条件下接受；障碍应在产生运动指令前阻断。

当前验收产物为`artifacts/kinematics_k2_release_v2`（综合结果`suite.json`），原A–F/R1/旧双臂回归为`artifacts/kinematics_k2_regression`。v2进一步将生成网格和具名碰撞对/阈值写入几何与策略摘要；旧`kinematics_k2_release`及失败的开发产物均保留，不替换最终验收记录。中文读数图、CSV和真实模拟TCP评分仅用于合成流程展示；没有把闭环对中误差写成运动学标定精度。

本轮本机结果：综合suite的10项检查通过，四个测点各一次修正后满足30µm阈值，接受窗口平均三表残差最大1µm。后续单独使用实际模拟状态评分，窗口内最大TCP位置误差约0.94µm，仅对本合成模型成立。完整回归为147项Python、4项CTest和114项冻结数值对照；收紧网格/碰撞对摘要后再运行17项K2专项通过，另补2项过期/无效关节反馈恢复保护反例通过。当前源码包含这些新增测试，未将它们重复累加成同一次完整测试数量。独立CMake/ament消费者及最终隔离wheel检查也通过；Windows和新版M2–M6完整采集未在本轮重跑。

后续K3仍需几何参数雅可比、规范自由度处理、MDH/Hayati映射、充分激励选点和独立数据划分。K2的少量成功对中点不解除这些门槛。K5还需实测球架与表架、实际接触/负载、硬件限制、时钟、掉线和停止能力。
