# DVT2模型替换计划

2026-11-02。默认机器人模型将整体替换为`~/下载/casbot_hl12p1_dvt2`提供的DVT2模型。迁移完成后，动力学、运动学、SDK Mock、碰撞和只读显示使用同一模型来源；旧nominal不再作为运行选项或自动回退。

当前状态：**N1已完成：五套原始模型与公共资源入库、LFS及资源访问/安装验证就绪。尚未派生14轴模型、生成新场景或切换默认值。** 开始规划时Git工作区干净，基线提交为`f06885a`（better hardware & sdk compability），Git LFS 3.8.1可用。每轮完成后更新本文进度及实际证据位置。

## 已确定的范围

- 新模型来自上述DVT2目录，不从439MB整机STEP重新造一份URDF。
- 原始模型和必要网格纳入仓库，大型网格/纹理用Git LFS；运行和安装后不依赖用户的下载目录。
- 整机固定，腰部锁定，只保留双臂14个活动自由度。其他关节的锁定姿态显式配置，保留固定部件所需的几何、frame及惯性。
- 场景重新定义、检查并冻结，不能直接沿用旧夹具、地面、障碍物和球架的世界坐标或碰撞缓存。
- Pinocchio负责模型约简、FK和动力学，Coal负责碰撞，Boost.Odeint继续积分；MuJoCo只显示。
- 沿用现有SDK五字段控制、500Hz客户端默认值、位置插值约定及故障终止规则，不复制驱动、采集器或机械内核。
- 保留现有CLI/设备接口的用途及数据含义；**默认模型数值和模型身份改变是本次明确接受的契约变更**。模型身份不同的旧批次不能混用或续采。

旧模型和旧数值结果保留在Git历史、历史文档和已有实验目录中，不为保留旧默认而继续维护两套运行分支。准备期间的N1/N2尚未改变现有入口；N3才统一切换。

## 已完成的只读勘查

源目录含`a2`、`a2_ff`、`b1`、`b2`、`b3`五套URDF/MJCF，共用约136MB的`assets/`。五套均已由Pinocchio读入，并在非双臂关节零位锁定的试验条件下约简到14轴，关节名称与顺序匹配现有双臂接口。

- `a2/a2_ff/b2`包含普通双手；`a2_ff`的手指已固定。零位锁定后，这三套的双臂关节放置和活动臂惯性数值一致，整机其他部件/几何仍须按选定配置处理。
- `b1`包含右侧吉他手，`b3`包含双侧鼓槌。部分末端link未给惯性，不能将缺失属性视为真实工具质量为零。
- 普通双手源URDF引用的网格均能从`assets/`解析。URDF网格路径本身没有包含`../assets`，导入器需要显式资源根目录。
- 旧模型零位腰部frame平移为`[0,0,0.15424]m`，新普通手模型为`[0,0,1.040582]m`，Z相差`0.886342m`。这反映模型坐标约定，不能直接作为实际安装高度。
- 当前模型加载、碰撞缓存和运动学导出仍绑定bundled nominal，需要一起迁移。

### 默认末端装配仍需冻结

用户已确定整个模型来源替换为DVT2，但尚未明确千分计标定时保留普通手，还是拆手后在腕部安装三表工装。N1可先导入所有源配置；**N2冻结默认装配前需确定该项**。

若保留普通双手，优先以`a2_ff`为基础；若拆手，则按实际安装接口从源模型移除相应手部子树、添加三表工装。不能仅因为目录名称选取`b3`，也不能把未答复解释为拆手。下载目录中的三表STEP可作为后续工装几何输入，质量、质心与TCP另记来源。

这项确认只影响装配派生和默认选择，不阻断原包入库、资源解析与公共接口准备；现场安装变换/设备证据在实机执行前补齐。

按N1→N2→N3→N4推进，每轮使用独立生成目录，完成后再进入下一轮。模型源数据、派生规则及配置入版本控制；原始采集、构建、日志、生成视频与大型可再生缓存仍按现有规则忽略。

每轮在可用、可验证的边界准备提交，不并发修改同一模型身份或共享写入区。提交使用本机Git信息，提交/推送按用户当轮授权执行；不以reset/clean清空其他工作。恢复旧实验使用Git历史和原始输入，不恢复一个隐藏的旧默认。
