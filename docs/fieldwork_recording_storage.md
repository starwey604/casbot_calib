# Fieldwork记录瘦身

## 新会话只保留一套原始记录

GUI的持续观测进程保存主反馈、debug、模式和IMU。每次手动控制及GUI回零不再另启原始记录器，而是在`capture/raw_reference.json`中记录：

- 指向该次持续观测原始目录的相对路径；
- 本次执行的本机接收区间`[start_receive_ns,end_receive_ns)`；执行中终点为`null`；
- 本机单调时钟域。区间包括启动等待和停止收尾，不是设备采样时间或执行器回调时刻。

执行器自身的`capture/execution/commands.csv`、`feedback.csv`、`events.csv`仍保留。这份反馈记录用于核对执行器实际收到什么，与共享观测进程的接收时刻分开。

保存清单使用`casbot_fieldwork_recording_v3`，快照使用`casbot_fieldwork_snapshot_v3`。快照必须保存完整工作区，包含被引用的持续观测；仅保存控制子目录会明确报错。搬动整份快照后，相对引用仍有效。恢复缓存只打开记录，不连接、不自动续采或发送。

共享观测记录器退出时，执行监督会终止控制并禁止该控制会话resume。PID和进程启动tick仅用于核对本机记录进程，运行时间戳和时钟域也不作为设备身份或采样时刻。

## 后台压缩保留每帧JSON和原始CDR

GUI原始目录位于`observations/<观测编号>/capture/raw/`：

```text
raw/
  format.json             # casbot_raw_gzip_frames_v2格式说明
  recorder.json           # 记录器时钟、QoS、进程等元数据
  publishers.jsonl        # 端点观测
  chunks/
    00000000.bin.gz       # 已封存块
    00000001.open.gz      # 活动或中断块
```

每块使用gzip level 1。解压后是7字节`CBRAW2\n`，随后重复：两个小端uint32长度（JSON字节数、CDR字节数）、UTF-8 JSON、原始CDR。JSON保留通道、消息类型、发布stamp、本机接收纳秒、局部序号和全轴字段；CDR逐字节保留，包括JSON无法表达的NaN/Inf位模式。`cdr_offset`是跨块连续的逻辑偏移，不是gzip文件中的seek位置。

约4 MiB未压缩载荷或1秒有数据时换块，允许单个提交批次超出块目标。记录回调约20ms提交一次，独立线程负责压缩、flush和文件写入。队列默认32 MiB；队列满或写盘失败后停止后续记录，报告具体原因，保留前缀，不覆盖旧帧、不阻塞发送进程。正常结束排空已接受的批次。

硬杀可能丢失尚在队列或尚未flush的尾段；已有`.open.gz`按完整帧前缀恢复，不要求其拥有完整gzip尾部。已封存`.bin.gz`必须有完整gzip校验尾部，解码时检查CDR长度、局部序号和逻辑偏移连续性；缺块、损坏不静默拼接。原始序号仅表示本机回调顺序。

保存活动会话时，已封存块直接复制；活动块只取完整帧并重新封成带校验尾部的gzip块。不同文件各有自己的截取位置，不制造共同采样瞬间。读取和复制每次只打开一个数据块，不整段解压到内存，也不因长记录耗尽文件描述符。

程序化读取：

```python
from casbot_calib.raw_archive import iter_records

for packet, cdr in iter_records("保存目录/observations/观测编号/capture/raw"):
    print(packet["channel"], packet["receive_ns"], len(cdr))
```

独立S1/H1–H4和非GUI调用维持其原生平面记录合同；本次改造不改变正式S3/S4观测规则。

## 回读按需导出，命令与反馈不再复制

`recording/recording.json`只引用唯一执行表和共享原始记录，不生成`recording/*.csv`副本。需要主反馈/debug对照时：

```bash
bash fieldwork/run.sh export-readback \
  --run '保存目录/controls/控制编号/runs/运行编号' \
  --output /tmp/readback.csv --start 1 --end 3 --joint 0 --joint 7
```

在本次执行所引用的原始区间内，以第一条joint/debug接收时刻为起点选取[1,3)秒，输出轴0和7。省略时间窗导出全程，省略轴参数导出14轴；整数纳秒、缺失字段和数值相同的全部帧均保留。分析、姿态恢复和视频不依赖导出副本；IMU分析直接读取同一份压缩观测。

## 显式输出与自有Mock共用记录额度

`--cache-limit-mib`作用于所有新建GUI记录工作区，默认512 MiB：

- 自动缓存：统计缓存目录及其中工作区、自有Mock。
- 显式`--output`：统计实际输出目录。
- `--mock --output`：缓存内的自有Mock与外部工作区合并统计，不重复计数嵌套目录；共用停录标记。
- 恢复新工作区：沿用原额度绑定。

约每秒检查一次，达到额度后停止追加持续观测、手动指令/反馈及自有Mock诊断；发送、实时反馈和停止通道继续。GUI回零也使用共享观测与该停录标记；规划必需的短起点执行反馈、参考和最终结果仍生成。额度是软限额，检查间隔内新增量、已入队尾段与收尾元数据可超出。

GUI顶部显示磁盘已用容量、最近检查区间的写入速度和预计剩余秒数。保存仍是独立前缀快照，不会删除活动缓存；多次保存产生多份存档，存档不计入活动记录额度。停止发送后持续观测仍录制，断开连接才结束该观测。

## 大CSV分析与视频读取：第三轮

原来的`a-evidence`命令和GUI“导出运动视频”直接使用新读取路径，无需改参数或手工切分CSV。

### 全程统计精确，拟合只保留选窗

- 指令与反馈逐行读取，全部行仍计入收发频率、非递增间隔、缺失值和发送迟到统计。
- p50/p95/p99/最大值采用临时SQLite中的整数纳秒频数表，按原NumPy线性分位数规则精确求值，不抽样、不近似。
- 只有`--window START END`内的反馈进入拟合内存，另保留全程首末行用于原覆盖检查。窗口若在原始行序中不连续，仍拒绝计算，不因裁剪而掩盖问题。原Fourier/同带宽算子、力矩错位对照和参数定义不变。
- IMU均值、方差和峰值在线累计。需要窗口拟合时，有效IMU写入同一临时数据库，再按窗口读取；重复帧和重复时间戳不会被合并。仍按同一时钟域与原有覆盖条件选择观测源。

暂存位于`--output`目录内，SQLite页缓存为4 MiB；正常完成、异常和键盘中断会清理暂存。长记录建议输出到磁盘目录，而非内存型`/tmp`。临时磁盘失败会明确终止分析，不退回近似统计；硬杀留下的未完成输出可人工清理。内存不再随整段CSV行数线性增长，但拟合矩阵仍随所选窗口样本数、时长和带宽增长，不会自动缩短窗口或降低带宽。

### 视频只读取当前位置与下一帧

视频按整数接收纳秒在20 fps时间网格上做零阶保持；同一时刻有多条反馈时取最后一条，最后一帧的25 ms取整规则保持。只解析14轴位置，不将整个CSV转换为NumPy表，也不预先创建全程视频时间数组。

读取CSV和输出帧时都检查取消请求。列数错误、非有限位置、接收时刻倒退会报错；不排序、不插值，也不静默丢弃异常行。失败或取消会关闭编码器，不发布最终`motion.mp4`，可能留下未完成的`motion.pending.mp4`。反馈相同仍正常生成20 fps视频帧。
